## The problem

Analysts, founders, and engineers need answers that depend on current information: what changed, who said it, and whether a claim holds up. Relying on model recall alone yields stale information and cannot cite sources. A good outcome is a concise brief in which every material claim links to a retrieved source with a publication date, contradictions are surfaced, and the research cutoff time is stated.

## Prompt

Give this to your agent (Claude Code, Cursor, Codex, and others) once AIsa is [connected via MCP](/agent-quickstart):

```txt wrap
Use AIsa to research: <your question>. Time range: <e.g. last 90 days>. Preferred sources: official docs, filings, original announcements, peer-reviewed papers.
Find the right AIsa search tools with `search`, and quote each paid call with `get_details` first. Ask me before any paid call, and tell me the expected number of calls.
Retrieve before you synthesize: search for candidates, then fetch the full text of every source you cite. Do not cite anything you did not retrieve.
Return a brief with: (1) verified facts, each with URL and publication date; (2) interpretation; (3) contradictions between sources; (4) open questions; (5) the research cutoff time.
```

For academic questions, replace the source line with: `Use scholarly sources only; include authors, year, and venue for each paper.`

## APIs and Skills used

Through MCP, your agent reaches these via five tools at `https://mcp.aisa.one/mcp`: `search`, `list_categories`, and `get_details` are free; `use` and `batch_use` are billed per call.

| Step | What the agent calls | Reference |
| --- | --- | --- |
| Discover sources | Web search with extracted page text | [Tavily Search](/api-reference/search/post_tavily-search) |
| Read full pages | Content extraction for URLs it already has | [Tavily Extract](/api-reference/search/post_tavily-extract) |
| Multi-pass answer with citations | Perplexity Sonar Pro | [Sonar Pro](/api-reference/perplexity/post_perplexity-sonar-pro) |
| Academic papers | Scholarly article search | [Search Scholarly Articles](/api-reference/scholar/post_scholar-search-scholar) |
| Recent cross-platform signal | 30-day brief across social and web sources | [Last 30 Days](/agent-skills/last30days) |
| Reusable workflow | Web, scholar, Tavily, and Sonar in one Skill | [Multi-source Search](/agent-skills/multi-source-search) |
| Synthesis | A supported model, after retrieval | [Models](/guides/models) |

Use a Skill when the research method is reusable. Call APIs directly when your application must control source selection, sequencing, caching, or ranking.

## Example output

<Note>Illustrative only. Names, URLs, and dates are placeholders, not real data.</Note>

```md
## Brief: Has Example Corp shipped its v2 API? (cutoff: 2026-01-15 09:00 UTC)

Verified facts
- Example Corp announced v2 general availability on 2026-01-10. [example.com/blog/v2-ga, 2026-01-10]
- The v1 endpoints are deprecated, not yet removed. [docs.example.com/changelog, 2026-01-11]

Interpretation
- Migration pressure is moderate: no removal date is published.

Contradictions
- A third-party post says v1 shuts down in March; the official changelog gives no date. [example.org/news/123]

Open questions
- Pricing for v2 is not stated in any retrieved source.
```

## Guardrails

- **Retrieve, then synthesize.** Snippets and model recall are leads, not evidence. Fetch the full source for any material claim.
- **Prefer primary sources.** Prioritize primary sources (official docs, filings, original announcements, datasets) and record both the URL and publication date.
- **Surface contradictions.** Report conflicting information instead of merging it, and mark claims that rest on a single source.
- **No invented citations.** The model must not cite or claim access to sources that were not retrieved.
- **Verify before delivery.** Verify that each citation resolves, recheck time-sensitive numbers, remove unsupported claims, and state the research cutoff time.
- **Quote, then ask.** `get_details` returns a free quote; pass the approved amount as `max_price_usd` on endpoints that support it. It checks the estimate, not the final charge. See [Billing & Credits](/guides/pricing).
- **Load only what you need.** Ingest only the selected Skill or API documentation pages, [Authentication](/guides/authentication), and [Models](/guides/models). Do not load the entire API reference.
- **When AIsa may not be necessary:** A single specialized search provider can be simpler if you use only one source type, need no reusable Skills, and already manage your own model and billing integrations. See [When to use AIsa](/how-it-works#when-to-use-aisa).
