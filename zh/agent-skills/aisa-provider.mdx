**将 AIsa 用作 OpenClaw 模型 Provider**。配置 OpenClaw，通过单一网关访问 Qwen、DeepSeek、Kimi、GLM 等模型。

## 安装

<CodeGroup>
```bash npx skills
npx skills add AIsa-team/agent-skills --skill aisa-provider
```

```bash AIsa CLI
npm install -g @aisa-one/cli
aisa skills install aisa-provider
```
</CodeGroup>

安装后启动新的智能体会话以加载该 Skill。

## 快速设置

### 选项 1：环境变量（最快）

```bash
export AISA_API_KEY="your-key-here"
```

OpenClaw 会自动检测 `AISA_API_KEY` 并将 AIsa 注册为 Provider。无需修改配置文件。

### 选项 2：交互式引导配置

```bash
openclaw onboard --auth-choice aisa-api-key
```

### 选项 3：带 Key 的 CLI 命令

```bash
openclaw onboard --auth-choice aisa-api-key --aisa-api-key "your-key-here"
```

### ⭐ Kimi K2.5——企业级 ZDR 路由

Kimi K2.5 是由 AIsa 企业级零数据保留（Zero Data Retention，ZDR）协议覆盖的 Moonshot 路由。

**主要特性**：
- 强大的推理与多步骤问题解决能力
- 在代码和数学基准测试中表现出色
- 通过 AIsa 与 Moonshot 的合作伙伴关系提供

#### 🔒 零数据保留（ZDR）——企业级隐私保护

通过 AIsa 访问 Kimi K2.5 享有**企业级零数据保留（Zero Data Retention）** 保证。用户无需担心数据隐私——AIsa 已与 Moonshot AI 签署正式的 ZDR 协议。

在 AIsa 与 Kimi（Moonshot AI PTE. LTD.）签署的**企业补充服务协议（Supplemental Enterprise Service Agreement）** （日期为 2026 年 2 月 10 日）约束下：

- **Moonshot 在处理后不会保留客户数据**
- **生成的内容不会存储**在 Moonshot 的基础设施上
- **任何数据均不会用于模型训练**——你的提示词与补全结果均保持私密
- 处理过程受企业契约条款约束，而非消费者服务条款（ToS）

这使 AIsa 成为需要访问 Kimi K2.5 且对隐私敏感或企业级工作负载的推荐途径。直接通过 Moonshot 的消费者 API 调用 Kimi K2.5 时，适用标准消费者数据政策；而通过 AIsa 路由，你的数据将享有协商达成的 ZDR 保护。

**⚠️ 重要提示：Temperature 限制**

Kimi K2.5 **仅接受 `temperature=1.0`**。使用任何其他值都将返回错误：
```
Error: invalid temperature: only 1 is allowed for this model
```

如果你的 OpenClaw 配置或智能体设置了不同的 temperature，请为 Kimi 单独覆盖设置：
```
/model aisa/kimi-k2.5
```
未显式设置时，OpenClaw 将使用模型的默认 temperature。

> 该路由当前的 AIsa 费率：https://aisa.one/models

## 模型 ID 版本控制

AIsa 对某些模型使用**带版本的模型 ID**。如果你遇到 `503 - No available channels` 错误，可能需要更新模型 ID。

**已知模型 ID 映射**：

| 通用名称 | 正确的 AIsa 模型 ID | ❌ 无法使用 |
|-------------|----------------------|------------------|
| Qwen Plus | `qwen-plus-2025-12-01` | `qwen3-plus`, `qwen-plus`, `qwen-plus-latest` |
| Qwen Flash | `qwen-flash` | `qwen3-flash`, `qwen-turbo`, `qwen-turbo-latest` |
| Qwen MT Flash（翻译） | `qwen-mt-flash` | `qwen-mt`, `qwen-translate` |
| Qwen Max | `qwen3.7-max` | （可直接使用） |
| DeepSeek V4 Pro | `deepseek-v4-pro` | （可直接使用） |
| Kimi K2.5 | `kimi-k2.5` | （可直接使用） |
| Kimi K3 | `kimi-k3` | `kimi-k3-latest`, `kimi-3` |

检查最新可用模型 ID：
```bash

```

## 故障排查

### “503 - No available channels” 错误
模型 ID 可能不正确或已过时。请查看上方的**模型 ID 版本控制**章节以获取正确 ID。常见修复方法：
- `qwen3-plus` -> 改用 `qwen-plus-2025-12-01`
- `qwen3-flash` -> 改用 `qwen-flash`（翻译任务使用 `qwen-mt-flash`）

### “Model not found” 错误
确保 OpenClaw 配置中的模型 ID 包含 `aisa/` 前缀：
```
✅ aisa/qwen3.7-max
❌ qwen3.7-max
```

### Kimi K2.5 “invalid temperature” 错误
Kimi K2.5 仅接受 `temperature=1.0`。如果你的配置设置了其他 temperature，请添加针对该模型的特定覆盖配置，或让 OpenClaw 使用默认值。

### Kimi K2.5 返回空响应
在极少数情况下，Kimi K2.5 可能会在消耗输出 token 的同时返回空内容。请重试请求——这种情况通常是暂时的。

### 未检测到 API key
1. 检查环境变量：`echo $AISA_API_KEY`
2. 或在配置中验证：`openclaw config get auth.profiles`
3. 重新运行引导配置：`openclaw onboard --auth-choice aisa-api-key`

### 流式传输无法正常工作
AIsa 使用兼容 OpenAI 的 API（`openai-completions`）。确保你的配置中包含：
```json
"api": "openai-completions"
```

### 速率限制或每日上限
AIsa **没有每日请求上限**（不同于限制 2,000 请求/天的免费 Qwen Portal）。

## 获取 API Key

1. 访问 https://console.aisa.one/
2. 注册并创建 API key
3. 将其设置为 `AISA_API_KEY` 或使用引导配置向导

## 注意事项

- AIsa 的端点兼容 OpenAI（`https://api.aisa.one/v1`）
- 所有模型均支持流式传输与函数调用（function calling）
- Qwen 模型的 `supportsDeveloperRole` 设置为 `false`
- 各模型的上下文窗口各不相同；请参阅[模型目录](/zh/guides/models)，切勿预设默认值
- 所有默认模型均已启用推理（思考）能力
- Kimi K2.5 必须使用 `temperature=1.0`——其他值会导致 API 报错
- 通过 AIsa 调用的 Kimi K2.5 受企业级零数据保留（ZDR）保护——数据不会被保留或用于训练
- 图像/视频生成模型（WAN）可用，但需要单独配置
- 截至 2026 年 10 月 16 日，AIsa API 支持 103 款模型——使用 models 端点可获取当前模型列表

## 开始使用

1. 在 [aisa.one](https://aisa.one) 注册并在控制台中创建 API key。
2. 在你的 Shell 中设置环境变量：`export AISA_API_KEY="your-key"`。
3. 使用[安装](#安装)中的任一命令安装该 Skill，然后启动新的智能体会话。
