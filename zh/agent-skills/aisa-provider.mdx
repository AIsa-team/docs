**将 AIsa 用作 OpenClaw 模型 provider。** 配置 OpenClaw，通过一个 gateway 访问 Qwen、DeepSeek、Kimi、GLM 以及其他模型。

## 安装

如果尚未安装 AIsa CLI，请先安装：

```bash
npm install -g @aisa-one/cli
```

然后安装这个 skill：

```bash
aisa skills install aisa-provider
```

## 快速设置

### 选项 1：环境变量（最快）

```bash
export AISA_API_KEY="YOUR_AISA_API_KEY"
```

OpenClaw 会自动检测 `AISA_API_KEY`，并将 AIsa 注册为 provider。无需修改配置文件。

### 选项 2：交互式 onboarding

```bash
openclaw onboard --auth-choice aisa-api-key
```

### 选项 3：通过 CLI 传入 key

```bash
openclaw onboard --auth-choice aisa-api-key --aisa-api-key "YOUR_AISA_API_KEY"
```

### ⭐ Kimi K2.5 — Moonshot AI 旗舰模型

Kimi K2.5 是 Moonshot AI 最新的推理模型，可通过 AIsa 访问，价格约为 **Moonshot 官方价格的 80%**。

**核心特性：**
- 强推理和多步骤问题求解
- 在 coding 和数学 benchmark 上表现有竞争力
- 通过 AIsa 与 Moonshot 的合作关系提供

#### 🔒 Zero Data Retention（ZDR）— 企业级隐私

通过 AIsa 访问 Kimi K2.5 时，附带**企业级 Zero Data Retention** 保障。用户无需担心数据隐私：AIsa 已与 Moonshot AI 签署正式 ZDR 协议。

根据 AIsa 与 Kimi（Moonshot AI PTE. LTD.）之间的 **Supplemental Enterprise Service Agreement**（2026 年 2 月 10 日）：

- Moonshot 处理后**不会保留 customer data**
- Moonshot 基础设施**不会存储生成输出**
- 数据**不会用于模型训练**，你的 prompts 与 completions 保持私密
- 处理流程受企业合同条款约束，而不是 consumer ToS

这使 AIsa 成为需要访问 Kimi K2.5、且对隐私敏感或面向企业 workload 的推荐路径。如果直接调用 Moonshot consumer API，适用的是标准 consumer data policy；通过 AIsa 路由后，你的数据会受协商后的 ZDR 保护。

**⚠️ 重要：temperature 限制**

Kimi K2.5 **只接受 `temperature=1.0`**。使用其他值会返回错误：

```
Error: invalid temperature: only 1 is allowed for this model
```

如果你的 OpenClaw 配置或 agent 设置了不同 temperature，请为 Kimi 覆盖模型：

```
/model aisa/kimi-k2.5
```

未显式设置时，OpenClaw 会使用模型默认 temperature。

## Model ID 版本管理

AIsa 对部分模型使用**带版本的 model ID**。如果遇到 `503 - No available channels` 错误，可能需要更新 model ID。

**已知 model ID 映射：**

| 常用名称 | 正确 AIsa Model ID | ❌ 不可用 |
|-------------|----------------------|------------------|
| Qwen Plus | `qwen-plus-2025-12-01` | `qwen3-plus`, `qwen-plus`, `qwen-plus-latest` |
| Qwen Flash | `qwen-mt-flash` | `qwen3-flash`, `qwen-turbo`, `qwen-turbo-latest` |
| Qwen Max | `qwen3-max` |（原样可用）|
| DeepSeek V3.1 | `deepseek-v3.1` |（原样可用）|
| Kimi K2.5 | `kimi-k2.5` |（原样可用）|

检查最新可用 model ID：

```bash
curl https://api.aisa.one/v1/models -H "Authorization: Bearer $AISA_API_KEY"
```

## 故障排查

### “503 - No available channels” 错误

model ID 可能不正确或已过期。查看上方 **Model ID 版本管理** 章节获取正确 ID。常见修复：
- `qwen3-plus` -> 使用 `qwen-plus-2025-12-01`
- `qwen3-flash` -> 使用 `qwen-mt-flash`

### “Model not found” 错误

确保 OpenClaw config 中的 model ID 使用 `aisa/` 前缀：

```
✅ aisa/qwen3-max
❌ qwen3-max
```

### Kimi K2.5 “invalid temperature” 错误

Kimi K2.5 只接受 `temperature=1.0`。如果你的 config 设置了不同 temperature，请添加模型级 override，或让 OpenClaw 使用默认值。

### Kimi K2.5 空响应

极少数情况下，Kimi K2.5 可能返回空 content，同时消耗 output tokens。重试请求即可，这通常是暂时性问题。

### 未检测到 API key

1. 检查环境变量：`echo $AISA_API_KEY`
2. 或在配置中验证：`openclaw config get auth.profiles`
3. 重新运行 onboarding：`openclaw onboard --auth-choice aisa-api-key`

### Streaming 不工作

AIsa 使用 OpenAI-compatible API（`openai-completions`）。确保你的 config 包含：

```json
"api": "openai-completions"
```

### Rate limits 或 daily caps

AIsa **没有 daily request limits**（不同于免费 Qwen Portal 的 2,000 req/day 上限）。

## 获取 API Key

1. 访问 https://console.aisa.one/
2. 注册并创建 API key
3. 将其设置为 `AISA_API_KEY`，或使用 onboarding wizard

## 说明

- AIsa endpoint 与 OpenAI 兼容（`https://api.aisa.one/v1`）
- 所有模型都支持 streaming 与 function calling
- Qwen 模型的 `supportsDeveloperRole` 设置为 `false`
- 默认上下文窗口：256,000 tokens（Qwen）或 131,072 tokens（DeepSeek/Kimi）
- 所有默认模型都启用 reasoning（thinking）
- Kimi K2.5 要求 `temperature=1.0`，其他值会导致 API 错误
- 通过 AIsa 使用 Kimi K2.5 受企业级 Zero Data Retention（ZDR）覆盖，数据不会被保留或用于训练
- Image/Video generation models（WAN）可用，但需要单独配置
- AIsa API 总共支持 49+ 个模型；使用 models endpoint 发现所有可用选项

## 开始使用

1. 在 [aisa.one](https://aisa.one) 注册（新账户有 $2 免费额度）。
2. 从 console 生成 API key。
3. 设置 key 并安装 skill：
   ```bash
   export AISA_API_KEY="YOUR_AISA_API_KEY"
   npm install -g @aisa-one/cli
   aisa skills install aisa-provider
   ```
4. 启动新的 agent session，让 runtime 加载更新后的 skill instructions。
