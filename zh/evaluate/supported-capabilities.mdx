AIsa 支持多种能力入口。可用性无法用一个静态数字表示：模型路由、API 提供商、Skills、MCP 描述符和带认证的写操作各有不同的发布和状态机制。

在基于某项能力开发之前，用本页确认正确的权威来源。

## AI 模型推理

AIsa 通过 `https://api.aisa.one/v1` 提供模型推理，支持 OpenAI 兼容以及部分提供商兼容的路由。

请查看：

- [实时模型目录](https://aisa.one/models)了解当前可用性。
- [模型指南](/zh/guides/models)了解模型 ID、能力术语和 endpoint 指引。
- [AI 模型价格](/zh/guides/pricing/ai-model-pricing-llm-inference)了解计费说明。

不要仅凭提供商家族名称推断模型可用性或模态支持。

## 直接数据和能力 API

AIsa 在 `https://api.aisa.one/apis/v1` 下提供非对话类 API。

[API 参考](/zh/api-reference)是查询精确方法、路径、参数、认证方式和示例的技术入口。涵盖领域包括搜索、研究、金融数据、社交平台、预测市场、媒体、公司与人员数据，以及当前参考文档中列出的其他提供商。

API 参考中的页面描述的是某条路由；投入生产前，仍需考虑当前健康状态、价格、速率限制和提供商特定要求。

## Agent Skills

[Agent Skills](/zh/agent-skills) 是面向受支持 agent 运行时的可复用指令包，可以组合模型、API、脚本、安全注意事项和输出规范。

请查看：

- Skill 页面上说明的触发场景和所用工具。
- Skill 的源码仓库，了解当前实现。
- 执行前需要的配置项。

Skill 不等于一个独立托管的服务，它教会 agent 如何使用底层能力。

## 带认证的写操作

有些 API 可以创建、更新、发送、发布、关注，或以其他方式改变外部系统。这类操作可能需要 OAuth 连接的账号或额外授权。

请把它们与只读 API 区别对待：

- 确认所需权限。
- 明确外部副作用。
- 在需要时获得确认。
- 执行后校验外部结果。

## 机器可读的发现

AIsa 发布了以下资源：

- [Agent Card](https://aisa.one/.well-known/agent-card.json)：面向 A2A 风格的高层发现。
- [MCP 目录](https://mcp.aisa.one/servers)：入口、module 与 server 的实时清单。
- [OpenAPI 规范](https://aisa.one/openapi.yaml)：请求和响应契约。
- [技术版 llms.txt](https://aisa.one/docs/llms.txt)：文档路由。

请检查发现资源中的 status 字段。处于规划状态的 MCP 描述符不应被当作已上线的 MCP server。

## 计费与支付

模型和 API 用量均为按量计费。请查阅：

- [价格与计费](/zh/guides/pricing)
- [钱包与支付](/zh/guides/pricing/wallet)
- [用量日志](/zh/guides/dashboard/usage-logs)
- [面向 agent 的机器支付](/zh/concepts/machine-payments-for-agents)

不要假设所有能力都使用相同的认证或支付路径。

## 验证清单

在依赖某项能力之前：

1. 确认它在模型、API、Skill 或发现资源中的实时条目。
2. 阅读确切的认证要求。
3. 查看价格和速率限制。
4. 用最小且安全的请求做测试。
5. 校验响应结构和失败行为。
6. 对写操作或支付，另行校验授权和副作用。

产品匹配方面的建议参见[何时使用 AIsa](/zh/evaluate/when-to-use-aisa)。
