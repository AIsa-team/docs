AIsa 对模型推理和计费型 API 能力采用按量计费。具体价格取决于所选的模型、路由或 endpoint，并且可能独立于本评估页面发生变化。

做最终决策时，请以最新的价格来源为准。

## 权威来源

- [AI 模型价格](/zh/guides/pricing/ai-model-pricing-llm-inference)：模型计费说明。
- [按次调用 API 价格](/zh/guides/pricing/per-call-api-pricing)：API 计费说明。
- [钱包与支付](/zh/guides/pricing/wallet)：充值和余额行为。
- [用量日志](/zh/guides/dashboard/usage-logs)：账户的实际用量。
- 实时模型目录或具体 API 页面：当前能力的上下文信息。

不要把对比文章或概念文章中的价格直接搬进生产逻辑。

## 估算完整工作流

多步骤的 agent 可能产生多笔费用。请估算：

1. 检索或 API 调用。
2. 模型的输入和输出 token。
3. 重试或降级路由。
4. 对入围记录的数据补全调用。
5. 媒体生成或其他按次计费的能力。

如果某个 endpoint 单价最低，却需要更多重试、token 或后续调用，它未必带来最低的整体任务成本。

## 预算控制

请定义：

- 单次 API 调用的成本上限。
- 单个任务的成本上限。
- workspace 的每日或每月上限。
- agent 是否可以选择更贵的降级方案。
- 达到什么金额需要确认。
- 余额不足时如何处理。

涉及运行时采购时，另请参见[面向 agent 的机器支付](/zh/concepts/machine-payments-for-agents)。

## 公平地比较备选方案

在把 AIsa 与直连提供商或其他网关比较时，应把以下因素纳入：

- 模型或 endpoint 价格。
- 接入额外提供商所需的工程投入。
- 计费和凭证管理。
- 需要用到的数据 API 或工具。
- 可靠性和降级需求。
- 可观测性和审计需求。

对于稳定的单一提供商场景，直连可能更简单。当工作流需要组合多个提供商或多种能力类型时，统一的能力层往往更有价值。

## 上线前的验证

- 确认精确的模型 ID 或 endpoint。
- 查看当前的计价单位。
- 跑一个有代表性的小请求。
- 检查用量记录。
- 衡量完整工作流，而不只是单次调用。
- 在放量之前先加上预算告警。

更宏观的产品决策参见[何时使用 AIsa](/zh/evaluate/when-to-use-aisa)。
