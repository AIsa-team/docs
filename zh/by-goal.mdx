当任务已经明确、但不确定该用 AIsa 的哪个产品入口时，可以参考本页。先从期望的结果出发，再选择相关性最高的最小路径。

## 研究与知识

用 AIsa 做证据收集、时事研究、学术检索、竞品研究或多来源综合。

- [多源搜索 Skill](/zh/agent-skills/search)：组合网页、学术、Perplexity 和 Tavily 来源。
- [Last 30 Days](/zh/agent-skills/last30days)：生成跨网页、社交、市场和社区的近期信号简报。
- [Scholar Search](/zh/agent-skills/scholar-search)：查找学术论文和学术来源。
- [Search API 参考](/zh/api-reference/search/get_youtube-search)：自行组合各个搜索 endpoint。
- [研究型 agent 用例](/zh/use-cases/research-agent)：选择检索和证据工作流。

## 市场与金融

用 AIsa 做公司研究、市场数据、财报文件、财务指标、预测市场、组合分析或跨来源趋势研究。

- [MarketPulse](/zh/agent-skills/marketpulse)：获取股票数据、财务数据、申报文件、分析师预期和宏观背景。
- [Trend Forecast](/zh/agent-skills/trend-forecast)：结合市场、新闻、社交信号和 LLM 综合分析。
- [Prediction Market Data](/zh/agent-skills/prediction-market-data)：查看 Polymarket 和 Kalshi 数据。
- [Financial API 参考](/zh/api-reference/financial/get_prices)：直接组合公司和市场 endpoint。
- [市场情报用例](/zh/use-cases/market-intelligence-agent)：设计更完整的市场研究 agent。

## 市场推广与数据补全

当 agent 需要公司发现、人员数据、联系人补全、创作者发现或销售研究输入时，使用 AIsa。

- [API 参考](/zh/api-reference)：浏览公司、人员、Apollo、WaveInflu 和数据补全 API。
- [SEO Keyword Research](/zh/agent-skills/seo-keyword-research)：构建关键词和竞品策略。
- [销售研究用例](/zh/use-cases/sales-research-agent)：规划以只读为先的公司和联系人研究工作流。

## 社交与媒体

用 AIsa 做 X/Twitter 情报、YouTube 研究、创作者发现、发布工作流或媒体生成。

- [Twitter Autopilot](/zh/agent-skills/twitter-autopilot)：结合 X/Twitter 研究和经审批的操作。
- [AIsa YouTube Search](/zh/agent-skills/aisa-youtube-search)：搜索视频、频道和播放列表。
- [Media Gen](/zh/agent-skills/mediagen)：通过受支持的模型路由生成图像或视频。
- [Twitter API 参考](/zh/api-reference/twitter/get_twitter-user-info)：单独控制读取和写入 endpoint。
- [社交情报 agent](/zh/use-cases/social-intelligence-agent)：设计来源受限的社交与媒体研究，并单独控制写操作。

当核心需求是推理、生成、编程、翻译、视觉或多模态处理时，使用模型推理。

- [模型目录](/zh/guides/models)：查看模型 ID、endpoint、能力以及实时目录指引。
- [Chat Completions API](/zh/api-reference/chat/post_chat-completions)：使用 OpenAI 兼容接口。
- [什么是 LLM 网关？](/zh/guides/learn/what-is-an-llm-gateway)：理解模型路由和统一计费。

## 自主操作与支付

只有当 agent 必须改变外部系统状态时，才使用带认证的写操作。只有在确认预算、授权和结算要求之后，才使用程序化支付能力。

- [按接口查找能力](/zh/by-interface)：对比 Skills、直接 API、模型、写操作、MCP、A2A 和支付。
- [AIsa 钱包与支付](/zh/guides/pricing/wallet)：了解账户充值和用量扣费。
- [面向 agent 的机器支付](/zh/concepts/machine-payments-for-agents)：判断何时适合使用程序化支付。
- [安全](/zh/guides/security)：查看数据处理和凭证要求。
- [自主 API 采购](/zh/use-cases/autonomous-api-purchasing)：把能力选择、授权、结算、交付和审计分开处理。

## 选择原则

优先选择能完成任务的最小产品入口：

1. 推理或生成用模型推理。
2. 需要完整可复用结果时用 Skill。
3. 需要自定义编排时用直接 API。
4. 只有必须产生副作用时才用带认证的写操作。
5. 只有在有明确预算和结算控制时才用程序化支付。

如需做整体产品匹配判断，请继续阅读[何时使用 AIsa](/zh/evaluate/when-to-use-aisa)。
