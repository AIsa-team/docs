---

<AccordionGroup>
  <Accordion title="需要单独注册或购买套餐吗？">
    不需要。所有 AIsa 账户都可以直接使用 AIsa Connect，用的就是现有的 API Key 和余额。见[价格与限制](/zh/resources/aisa-connect/pricing-and-limits)。
  </Accordion>
  <Accordion title="我的用户可以连接哪些应用？">
    用 `GET /apps`、[aisa.one/catalog/connectors](https://aisa.one/catalog/connectors) 或[控制台](/zh/resources/aisa-connect/console)查看实时目录。不需要用户账号的应用，以及 AIsa 通过自有 [Unified API](/zh/resources/unified-apis) 提供的平台，不在 Connect 目录里。想申请接入某个应用，在控制台点 **申请接入应用**，或写信到 [developer@aisa.one](mailto:developer@aisa.one)。
  </Accordion>
  <Accordion title="能连接多少个终端用户？提高上限要额外收费吗？">
    一个 AIsa 账户默认最多 10,000 个有效连接，按你所有终端用户合计。需要更多，写信到 [developer@aisa.one](mailto:developer@aisa.one)。连接本身不收费，上限调高也一样，只有成功的执行才计费。见[价格与限制](/zh/resources/aisa-connect/pricing-and-limits#连接数上限)。
  </Accordion>
  <Accordion title="用户授权 Google 时会看到“未验证应用”的提示吗？">
    不会。Google 应用通过已验证的 OAuth 应用连接，用户会直接看到 Google 正常的授权页，Google 对未验证应用的 100 个用户上限也不适用。授权页上显示的是 AIsa 为这个应用使用的 OAuth 应用名称，不是你的产品名，也不是“AIsa”。如果担心用户困惑，可以在连接前提前告诉他们。
  </Accordion>
  <Accordion title="可以从浏览器或移动端应用调用 AIsa Connect 吗？">
    带 API Key 不行。请从你的后端调用，只把托管会话的 `connectUrl` 发给终端用户。用 OAuth 登录的 MCP 客户端不需要 key。
  </Accordion>
  <Accordion title="没有真实用户，怎么测试？">
    在[控制台](/zh/resources/aisa-connect/console)连接你自己的账号，或者选一个测试用的 `externalUserId`（例如 `test_user_1`），按[快速开始](/zh/resources/aisa-connect/quickstart)走一遍。测试连接也计入连接数上限，用完请删除。
  </Accordion>
  <Accordion title="redirectUrl 需要先在 AIsa 登记吗？">
    不需要。发起会话时直接把你应用的任意 https URL 作为 `redirectUrl` 传进来，本地测试时也可以用 `http://localhost`。只有在你希望账户只接受自己的 URL 时，才需要写信到 [developer@aisa.one](mailto:developer@aisa.one) 设置跳转白名单。见[跳回你的应用](/zh/resources/aisa-connect/authorize-users#跳回你的应用)。
  </Accordion>
  <Accordion title="一个终端用户能连接同一个应用的两个账号吗？">
    不带 `connectionId` 再次连接同一个应用，可能会为同一个终端用户新增一个连接。不传 `connectionId` 的执行会使用这个应用下最新的 `active` 连接；传 `connectionId` 可以指定某一个。如果只是想刷新已有连接，请带 `connectionId` [重新连接](/zh/resources/aisa-connect/authorize-users#重新连接)。
  </Accordion>
  <Accordion title="用户在应用里撤销了授权会怎样？">
    应用报告这个连接的授权已失效时，执行返回 `409 reconnect_required`，连接变成 `needs_reconnect`，请让用户重新连接。如果应用只是拒绝这个账号执行某一个动作，执行会返回 `400 invalid_request`，连接仍是 `active`。AIsa 不在后台检查连接，所以要到下一次执行才会知道变化。
  </Accordion>
  <Accordion title="删除连接会撤销用户在应用里的授权吗？">
    删除后 AIsa 立即停止使用这个连接：它不再出现在列表里，执行也不能再用它。应用支持的话，用户在应用那边给的 OAuth 授权也会一起撤销。Google 要等使用同一个 Google 账号的最后一个活跃连接被删除时才撤销：只要还有别的连接在用这个账号，比如分别连接了 Gmail 和 Google 日历，授权会保留，那个连接才能继续用。用户可以在 **Google 账号 → 安全 → 您与第三方应用和服务之间的关联** 里查看。用户在应用里自己创建的 API key 等凭证不会被撤销，需要用户在应用里自己删除。
  </Accordion>
  <Accordion title="能拿到终端用户的 token，自己去调用应用吗？">
    不能。没有任何接口会返回终端用户的令牌或密钥，也没有可以透传任意应用 API 调用的接口。请使用应用的动作。
  </Accordion>
  <Accordion title="能用我自己的 OAuth 应用，或者给托管页换品牌吗？">
    暂时不能。托管 OAuth 使用 AIsa 注册的应用和 AIsa 的托管页。
  </Accordion>
  <Accordion title="有触发器或 webhook 吗？">
    暂时没有。应用里发生的事件、连接会话结束，AIsa 都不会通知你。连接结果请轮询 `GET /connect/sessions/{sessionId}`。
  </Accordion>
  <Accordion title="能把智能体限制为只执行只读动作吗？">
    可以，有三种方式：只把 `operationType` 为 `read` 的动作交给模型；找我们申请只有 Connect 只读权限（`connector:read`）的 API Key；另外，生产环境里 Google 应用本来就以只读权限连接。见[防护措施](/zh/resources/aisa-connect/agents#防护措施)。
  </Accordion>
  <Accordion title="为什么写操作返回 400 invalid_request？">
    提示 "the app refused this action for the connected account"，说明账号缺少这个动作需要的权限。生产环境的 Google 应用是只读的；其他应用请检查用户授予的权限，或者他们 key 的权限。
  </Accordion>
  <Accordion title="团队成员能共享连接吗？">
    连接归属于 API Key 所在的 AIsa 账户。这个账户的每个 key，以及以这个账户身份的 OAuth 登录，看到的都是同一批连接。目前还没有按成员或按连接分配的权限。
  </Accordion>
  <Accordion title="AIsa 会重试失败的执行吗？">
    不会。每次执行只发给应用一次。要安全重试，请带上 `Idempotency-Key`；见[重试和幂等](/zh/resources/aisa-connect/actions#重试和幂等)。
  </Accordion>
  <Accordion title="每分钟能执行多少次？">
    执行算写请求：每个 API Key 每分钟 60 次，你所有 Key 之上还有一个账户级的合计限制。目录、会话、连接这类读请求每分钟 300 次。超出会返回 `429 rate_limited` 并带 `Retry-After`，不收费。业务需要更高的额度，写信到 [developer@aisa.one](mailto:developer@aisa.one)。见[限流](/zh/resources/aisa-connect/pricing-and-limits#限流)。
  </Accordion>
  <Accordion title="有分页吗？">
    Connect API 本身没有分页：列表一次返回全部结果，`GET /apps` 的 `limit` 最大 5000。会分页读取应用数据的动作，在 `inputSchema` 里有自己的分页字段。
  </Accordion>
  <Accordion title="动作会返回什么？">
    每个动作的 `outputSchema`（`GET /actions/{actionKey}` 返回）描述了它的 `output`。例如 `gmail.fetch_emails` 返回 `messages`，每封邮件有 `messageId`、`threadId`、`sender`、`to`、`subject`、`snippet`、`messageTimestamp` 和 `labelIds`，还有更多结果时带 `nextPageToken`。字段名请以 schema 为准，不要猜。
  </Accordion>
  <Accordion title="一个连接能用多久？">
    连接会一直保持 `active`，直到你删除它，或者应用不再接受它的授权；那时它会变成 `needs_reconnect`。OAuth token 由 AIsa 自动刷新，你不用处理过期。
  </Accordion>
</AccordionGroup>

还有问题？见[错误与排查](/zh/resources/aisa-connect/errors)，或写信到 [developer@aisa.one](mailto:developer@aisa.one)。
