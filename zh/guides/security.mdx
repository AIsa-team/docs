AIsa 将请求路由到上游模型和数据提供商，并在设计上尽可能少地保留你的数据。

## 数据处理

- 请求会被实时处理，将每次调用路由到正确的上游提供商，响应直接返回给你。
- AIsa 不会将你的数据用于训练或分析。

## 提示词与输出的留存

AIsa 对请求内容遵循**无存储策略**：

- **提示词和输入不会被存储。**
- **响应和输出不会被存储。**
- 请求载荷仅在处理过程中短暂存在，请求完成后即被丢弃。

这适用于所有 API：模型、embeddings、视频、社交、网络搜索、学术和金融。

## 运营元数据

AIsa 仅保留运行和保护平台所需的有限元数据——请求时间戳、API key 标识符、端点和模型、token 数量与费用、速率限制计数器，以及状态或错误信息。此元数据**不**包含提示词、输入或输出，也不用于训练或内容分析。这就是你在[用量与日志](/zh/guides/dashboard/overview#usage-and-logs)中看到的内容。

## 认证与传输

- 每个请求都通过 API key 或 OAuth 会话进行认证；未认证的请求会被拒绝。参见[认证](/zh/guides/authentication)。
- 使用 MCP 和 CLI 时，OAuth token 由客户端持有并自动刷新。智能体不得读取、复制或重用客户端的 OAuth token。
- 所有端点仅通过 HTTPS 提供服务。协议版本和加密配置在基础设施层面管理。

你有责任妥善保管 API key、限制每个 key 的消费额度，并定期轮换 key。

## 上游提供商

为完成调用，AIsa 仅将该调用所需的数据转发给选定的提供商，不会多发任何内容。AIsa 不会在转发前后持久化请求内容。提供商对数据的处理受该提供商的条款约束；当你的用例有此需要时，请审阅相关条款。

对于敏感工作负载，请评估哪些字段会被发送、是否可以最小化或脱敏、适用哪些监管或合同约束，以及结果本身是否可能包含敏感数据。

## 智能体安全管控

- **状态变更操作**：对于在外部创建、更新、删除或发送数据的操作，确保你的智能体在执行前向用户确认目标和预期变更。切勿对有副作用的操作启用无限制的自动重试，并在报告成功前在外部系统中验证结果。有读取权限不等于有写入权限。
- **预算边界**：为每个智能体分配独立的 API key 并设置消费限额；该限额即为硬性上限。在声明支持最高价格的端点上，最高价格也会在调用任何提供商之前拒绝估算过高的请求；通过 MCP，`batch_quote` 会在 `batch_use` 执行前对确切的调用进行报价。两者都检查估算值，但不对最终收费设上限。参见[计费与额度](/zh/guides/pricing)。
- **运营韧性**：在生产环境中，配置超时、优雅处理速率限制、在余额不足时告警，并避免在应用日志中打印原始凭据。

## 安全审查问题清单

- 哪个能力和上游提供商将处理该请求？
- 发送了哪些数据，记录了哪些日志？
- 需要哪些凭据和权限？
- 该操作是否有外部副作用？
- 消费和重试如何设定边界？
- 有什么证据可以验证最终结果？

请根据具体端点或 Skill 页面来回答与特定能力相关的问题，而非依据通用的平台描述。
