AIsa 发布了多个机器可读的发现资源，让自主智能体无需人工介入即可发现、理解并调用 AIsa 的能力。本指南逐一介绍这些资源，解释集成流程，并提供 Python、TypeScript 和 Bash 的可运行代码示例。智能体遵循的规则（如何连接、验证、报价、批准支出和处理错误）只有一个来源：[智能体设置指南（agent setup guide）](https://aisa.one/llms.txt)；本页只指向它。

## 发现端点

AIsa 通过以下公开 URL 支持智能体和文档发现。这些资源读取时无需身份认证。

| 端点 | 协议 | URL | 用途 |
| :--- | :--- | :--- | :--- |
| **智能体卡片** | Google A2A | `https://aisa.one/.well-known/agent-card.json` | 高层能力及其元数据、标签、示例和输入/输出模式 |
| **AI 插件** | OpenAI Plugin (v1) | `https://aisa.one/.well-known/ai-plugin.json` | 兼容 ChatGPT 时代的智能体工具 |
| **MCP 服务器** | MCP（Streamable HTTP，OAuth） | `https://mcp.aisa.one/mcp` | 智能体连接的主要端点，通过浏览器 OAuth 登录（没有浏览器的客户端改为发送 `Authorization: Bearer $AISA_API_KEY`）。通过少量元工具（`search`、`list_categories`、`batch_get_schema` / `get_details`、`batch_quote`、`batch_use`、`use`、`account`）覆盖整个目录。参见[通过 MCP 连接](/zh/agent-quickstart) |
| **MCP 目录** | 实时 MCP 清单 | `https://mcp.aisa.one/servers` | 由运行中的 MCP 服务按请求生成的 JSON：`serverCount`、`toolCount`、根与分类 `entrypoints`、`modules`，以及每个提供商服务器一条记录（`slug`、`docsRef`、`documentHashes`、工具数量）和已加载的 `contract` 来源信息。只含计数：工具名称和 Schema 来自各端点的 `tools/list`。仅用于列表；连接请使用 `https://mcp.aisa.one/mcp` |
| **OpenAPI 规范** | OpenAPI 3.1.0 | `https://aisa.one/openapi.yaml` | 机器可读的请求和响应契约 |
| **MPP 支付发现** | OpenAPI 3.1 + `x-payment-info` | `https://api.aisa.one/openapi.json` | 无需 API Key、接受[机器支付](/zh/integrations/machine-payments)的端点 |
| **智能体设置指南（agent setup guide）** | llms.txt | `https://aisa.one/llms.txt` | 智能体规则的唯一来源：如何连接、验证、使用 MCP 工具、批准支出和处理错误 |
| **技术文档 llms.txt** | llms.txt | `https://aisa.one/docs/llms.txt` | 本文档站的索引；任何页面在 URL 后追加 `.md` 即可获得 Markdown |

## 智能体发现的工作方式

发现流程包含四个步骤：**发现**、**连接**、**检查**和**调用**。自主智能体先阅读智能体设置指南和智能体卡片，了解 AIsa 的能力；通过 MCP 连接；检查确切的工具契约；最后调用已报价的请求。使用 API Key 直接调用 HTTP 是无法使用 MCP 的代码的文档化回退方案（fallback）。

<Steps>
  <Step title="发现">
    智能体阅读[智能体设置指南](https://aisa.one/llms.txt)，并从 `aisa.one` 获取 `/.well-known/agent-card.json`。卡片中包含技能列表，每项技能都有 `id`、`name`、`description`、`tags` 和 `examples`。智能体使用这些元数据判断 AIsa 能否完成当前任务。
  </Step>
  <Step title="连接（MCP + OAuth，主要流程）">
    智能体把 `https://mcp.aisa.one/mcp` 添加为远程 MCP 服务器，并通过浏览器 OAuth 登录；无需粘贴任何 Key。没有浏览器的客户端改为在 MCP 配置中发送 `Authorization: Bearer $AISA_API_KEY`。然后用一次免费的受保护调用验证连接：`account` 操作（或 `use` 配合 `{"operation_id": "account"}`）。工具列表或 `401` 不算。参见[通过 MCP 连接](/zh/agent-quickstart)。
  </Step>
  <Step title="检查">
    通过 MCP，`search` 返回候选工具的确切名称、参数 Schema 和标价，`batch_get_schema`（也以 `get_details` 提供）返回最多 20 个工具的完整契约。HTTP 回退方案则获取 `/openapi.yaml`：参数类型、必填字段、身份认证要求和声明的定价。
  </Step>
  <Step title="调用">
    通过 MCP，智能体先用 `batch_quote` 对确切的调用报价，再用 `batch_use` 执行，并遵循[智能体设置指南中的支出规则](https://aisa.one/llms.txt)（报价返回 `auto_execute_eligible: true` 时自动执行，否则用一条消息给出报价总额请求批准）。HTTP 回退方案把请求连同 `Authorization: Bearer $AISA_API_KEY` 发送到 `api.aisa.one`，并遵循更严格的[直接 HTTP 规则](/zh/get-started/cli#直接-http-回退)；部分只读端点也接受[机器支付](/zh/integrations/machine-payments)而无需 Key。
  </Step>
</Steps>

## A2A 智能体卡片

[Google Agent-to-Agent（A2A）](https://google.github.io/A2A/)协议定义了智能体发布自身能力的标准格式。AIsa 的智能体卡片位于 well-known URL，用于描述平台、身份认证要求和完整技能目录。

### 获取智能体卡片

<CodeGroup>

```bash curl
curl -s https://aisa.one/.well-known/agent-card.json | jq .
```

```python Python
import requests

card = requests.get("https://aisa.one/.well-known/agent-card.json").json()
print(f"Agent: {card['name']} — {card['description']}")
print(f"Skills: {len(card['skills'])}")
for skill in card["skills"]:
    print(f"  • {skill['id']}: {skill['name']}")
```

```typescript TypeScript
const res = await fetch("https://aisa.one/.well-known/agent-card.json");
const card = await res.json();
console.log(`Agent: ${card.name} — ${card.description}`);
console.log(`Skills: ${card.skills.length}`);
card.skills.forEach((s: any) => console.log(`  • ${s.id}: ${s.name}`));
```

</CodeGroup>

### 智能体卡片结构

顶层字段描述智能体身份、身份认证和能力：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `name` | string | 智能体名称，例如 `"AIsa"` |
| `description` | string | 智能体用途的一句话摘要 |
| `url` | string | API 请求的基础 URL，例如 `https://api.aisa.one` |
| `provider` | object | 组织名称和网站 |
| `version` | string | 智能体卡片的语义化版本 |
| `documentationUrl` | string | 供人阅读的文档链接 |
| `capabilities` | object | 功能标志，例如流式传输、推送通知和状态历史 |
| `authentication` | object | 支持的认证方案和凭证说明 |

### 技能对象

`skills` 数组中的每一项都描述一项能力：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | string | 唯一技能标识符，例如 `chat-completions`、`twitter-autopilot` |
| `name` | string | 供人阅读的技能名称 |
| `description` | string | 技能的用途和所提供的数据 |
| `tags` | string[] | 用于筛选和匹配的可搜索标签 |
| `examples` | string[] | 该技能可处理的自然语言示例查询 |
| `inputModes` | string[] | 接受的内容类型，默认为 `application/json` |
| `outputModes` | string[] | 响应内容类型，例如 `application/json`、`text/event-stream` |

## OpenAI 插件清单

为了兼容实现原始 ChatGPT 插件协议的智能体框架，AIsa 还在 `/.well-known/ai-plugin.json` 发布 `ai-plugin.json` 清单。该文件遵循 [OpenAI 插件 Schema v1](https://platform.openai.com/docs/plugins/getting-started)，并引用同一份 OpenAPI 规范。

```bash
curl -s https://aisa.one/.well-known/ai-plugin.json | jq .
```

清单包含 `description_for_model` 字段，列出关键 API 端点，帮助基于 LLM 的智能体无需解析完整 OpenAPI 规范即可理解可用工具。

## OpenAPI 3.1 规范

`/openapi.yaml` 上的合并版 OpenAPI 规范覆盖全部 111 多条 AIsa API 路径，并按 10 个类别组织。它是构造 API 请求的权威机器可读契约。

### 获取并解析规范

<CodeGroup>

```python Python
import yaml, requests

spec = yaml.safe_load(requests.get("https://aisa.one/openapi.yaml").text)
paths = list(spec["paths"].keys())
print(f"Total endpoints: {len(paths)}")
print(f"First 5: {paths[:5]}")
```

```typescript TypeScript

const res = await fetch("https://aisa.one/openapi.yaml");
const spec = YAML.parse(await res.text());
const paths = Object.keys(spec.paths);

```

## 端到端集成示例（HTTP 回退方案）

能使用 MCP 的智能体按上文的连接、检查、调用步骤，使用 `search`、`batch_get_schema`、`batch_quote` 和 `batch_use` 工具即可。下面的 Python 示例是无法使用 MCP 的代码的 HTTP 回退方案：智能体发现 AIsa 的能力，识别 `chat-completions` 技能，并发起经过身份认证的 API 调用。发起付费调用前，请遵循[智能体设置指南中的批准规则](https://aisa.one/llms.txt)和[直接 HTTP 规则](/zh/get-started/cli#直接-http-回退)。

```python
import requests

# Step 1: Discover — fetch the agent card
card = requests.get("https://aisa.one/.well-known/agent-card.json").json()

# Step 2: Find a skill by tag
target_tag = "llm"
matching = [s for s in card["skills"] if target_tag in s.get("tags", [])]
if not matching:
    raise RuntimeError(f"No skill found with tag '{target_tag}'")

skill = matching[0]
print(f"Selected skill: {skill['name']} ({skill['id']})")

# Step 3: Invoke — call the API using the base URL from the card
response = requests.post(
    f"{card['url']}/v1/chat/completions",
    headers={
        "Authorization": "Bearer YOUR_AISA_API_KEY",
        "Content-Type": "application/json",
    },
    json={
        "model": "gpt-5.4-mini",
        "messages": [
            {"role": "user", "content": "Summarize the A2A protocol in two sentences."}
        ],
    },
)

result = response.json()
print(result["choices"][0]["message"]["content"])
```

## 身份认证

通过 MCP 连接的智能体使用浏览器 OAuth 认证，无需处理任何 Key；没有浏览器的客户端在 MCP 配置中设置 `Authorization: Bearer $AISA_API_KEY`。HTTP 回退方案对 `api.aisa.one` 的每个请求使用同一个 Bearer Token：

```text
Authorization: Bearer YOUR_AISA_API_KEY
```

部分只读端点接受[机器支付](/zh/integrations/machine-payments)而无需 Key。`GET /v1/models` 成功只是传输层检查，不能证明已认证的业务访问。请用一次免费的受保护调用验证（MCP 的 `account`，CLI 的 `aisa balance`）。

从 [AIsa Dashboard](https://console.aisa.one) 生成 API Key。有关权限范围、轮换和安全存储的详细密钥管理指南，请参阅[身份认证](/zh/guides/authentication)。

<Warning>
  发现资源（`agent-card.json`、`ai-plugin.json`、`openapi.yaml`、`/servers` 和各 llms.txt 文件）可公开读取，无需身份认证；对 `api.aisa.one` 的 API 调用需要所选路由文档中记录的认证方式。
</Warning>

## 集成模式

### 模式 1：基于标签匹配技能

智能体可以使用 `tags` 数组将任务匹配到技能。对于需要在运行时动态选择能力的智能体，这是推荐方式。

```python
def find_skills_by_tags(card, required_tags):
    """Return skills that match ALL required tags."""
    return [
        skill for skill in card["skills"]
        if all(tag in skill.get("tags", []) for tag in required_tags)
    ]

# Find skills for financial research
finance_skills = find_skills_by_tags(card, ["finance", "stocks"])
# Returns: [MarketPulse Financial Data]
```

### 模式 2：基于示例匹配意图

对于基于 LLM 的智能体，`examples` 字段提供自然语言查询，可用于和用户意图进行语义相似度匹配。

```python
# Collect all examples with their skill IDs
example_index = []
for skill in card["skills"]:
    for example in skill.get("examples", []):
        example_index.append({"text": example, "skill_id": skill["id"]})

# Use an embedding model to find the closest match to the user's query
# user_query = "What's the stock price of Apple?"
# → Matches MarketPulse skill via "Get the current stock price for AAPL"
```

## CORS 支持

发现端点包含宽松的 CORS 响应头（`Access-Control-Allow-Origin: *`），因此基于浏览器的智能体和 Web 应用无需代理服务器即可直接获取数据。适用于：

- `/.well-known/agent-card.json`
- `/.well-known/ai-plugin.json`
- `/openapi.yaml`
