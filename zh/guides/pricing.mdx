AIsa 按用量计费。你充值一个统一余额，每次模型调用、数据 API 调用、MCP `batch_use` 和 CLI `call` 都从中扣费。你可以按需付费，也可以选择订阅计划；详见 [aisa.one/pricing](https://aisa.one/pricing)。

本文档说明**如何**计费，不列出具体价格——价格更新频率高于文档。当前价格：

- **模型**：[aisa.one/models](https://aisa.one/models) — 各模型的输入和输出单价，并排对比。
- **数据 API**：[aisa.one/api](https://aisa.one/api) — 每个提供商页面标注了端点是固定还是按量计费、参考价格及费用规则。

## 额度与充值

- 新账户自带免费额度用于测试。
- 在 [控制台 → Billing](https://console.aisa.one/billing)（或通过 CLI 执行 `aisa topup`）充值。支付在 Stripe 托管页面完成。
- 余额由你所有的 API key 和会话共享。设置了[消费限额](/zh/guides/authentication#密钥设置)的 API key 最多可消费其剩余限额与余额中较低的那个。
- 余额或 API key 限额耗尽时，请求会在调用任何提供商之前以 `402`（`insufficient_wallet_balance` 或 `insufficient_api_key_balance`）失败。少数高级端点还要求订阅；其 `402` 响应会说明这一点。

## 模型

模型调用按该请求报告的用量计费：

| 模型类型 | 计费依据 |
| --- | --- |
| 文本、代码和视觉模型 | 按每 1M token：输入和输出，加上路由报告的缓存读取和缓存写入（如有） |
| Embedding、rerank 和 classify 模型 | 按每 1M 输入 token |
| 图像模型 | 按请求（无论 `n` 要求生成几张图都只收一次）或按 token 计费，取决于具体模型 |
| 视频模型 | 按输出秒数或按每 1M token，不同分辨率有不同费率 |

对于 token 模型：`cost = input_tokens / 1,000,000 × input_price + output_tokens / 1,000,000 × output_price`，加上缓存桶（如有）。流式输出不影响价格。响应中的 `usage` 对象报告被计费的 token 数。

## 数据 API

数据 API 按请求计费，采用以下两种模式之一：

- **按次固定** — 对该端点的每次成功请求费用相同，不受响应大小影响。示例：Open-Meteo、CoinGecko、Polymarket、Kalshi、Apollo、EDINET、FRED。
- **按量** — 价格取决于请求消耗的内容（结果数、行数、页数或提供商额度），乘以你的计划倍率，因此随返回内容增长。示例：Twitter、Tavily、web search、Financial、YouTube、Scholar、Exa、Perplexity、Firecrawl、Semrush、Ahrefs、SimilarWeb、TikHub、DataForSEO。

部分端点（包括 SimilarWeb）采用额度公式。在付费请求前请阅读端点的参考页面了解公式；如果没有记录最大值，请勿在需要事先批准的策略下执行。

哪些情况计费：

- 已处理并返回结果的请求会被计费。每次成功的重试会再次计费，因此请谨慎重试。
- 在处理前被拒绝的请求——凭据错误、速率限制、余额不足、价格超出上限——不计费。
- 每次调用费率可能因计划或分组不同而异；实际扣费金额显示在 Usage 中。

通过 MCP，`search`、`list_categories`、`get_details` 和 `batch_quote` 免费；`batch_use` 按相同费率逐次计费。部分数据端点还支持通过 Machine Payments Protocol (MPP) 按请求付费，无需 API key；详见[机器支付](/zh/integrations/machine-payments)。

## 费用估算、报价与扣费

- **目录估算**：目录中的 `default_request_estimate_usd` 描述的是参考请求。它不是保证的起始价格、最大值或账单。
- **免费报价**：在支持 `X-AISA-Cost-Mode: quote` 的端点上，使用将要执行请求的 API key 发送完全相同的请求。报价反映你当前账户的定价。它不会调用上游提供商，也不会扣减余额。
- **账户倍率**：`billing_multiplier_ppm` 是你的倍率，单位为百万分之一；除以 1,000,000 即可。例如 1,000,000 表示 1×。发布的参考倍率不能替代你在认证报价中获取的倍率。
- **微美元单位**：费用字段使用整数微美元（1 USD = 1,000,000 微美元）。
- **结算费用**：执行后，REST 响应头 `X-AISA-Customer-Cost-Micros-USD`，或成功的原生 Tool 结果中的 `customer_cost_micros_usd`，在存在时报告客户费用。缺失费用元数据意味着未知，而非免费。Tool 的 `cost_estimate` 仍然是估算值，提供商费用不是你的扣款。通过 [用量](/zh/guides/dashboard/overview#用量) 和余额核对费用；解析细节参见 [API 参考](/zh/api-reference#已结算调用费用)。

## 先报价、再审核、后执行

使用当前端点参考中的完整 URL 和参数。以下 GET 示例适用于声明了报价和最高价格支持的端点。对于 POST 或其他方法，在两个步骤中保持相同的方法和请求体以及 URL。在环境中设置 `AISA_API_KEY` 和 `AISA_REQUEST_URL`；两个步骤使用相同的账户和请求参数。

首先，请求免费报价：

```bash
curl --fail-with-body --silent --show-error "${AISA_REQUEST_URL:?Set AISA_REQUEST_URL}" \
  --header "Authorization: Bearer ${AISA_API_KEY:?Set AISA_API_KEY}" \
  --header "X-AISA-Cost-Mode: quote" \
  --output quote.json
```

检查响应是否包含 `object: cost_estimate`。将 `estimated_cost_micros_usd` 除以 1,000,000 转换为 USD，不要向下取整。将 `AISA_MAX_PRICE_USD` 设置为你批准的金额。这是一个准入检查：如果执行估算超过你的限额，网关会在调用上游提供商之前以 `402` 拒绝请求。它不会限制最终费用。

审核通过后，执行相同的请求，**不带**报价头：

```bash
curl --fail-with-body --silent --show-error "${AISA_REQUEST_URL:?Set AISA_REQUEST_URL}" \
  --header "Authorization: Bearer ${AISA_API_KEY:?Set AISA_API_KEY}" \
  --header "X-AISA-Max-Price-USD: ${AISA_MAX_PRICE_USD:?Set AISA_MAX_PRICE_USD}"
```

MCP 提供相同的配对操作：`batch_quote` 返回完全相同调用的报价而不执行，`batch_use` 在审核后执行相同的调用。如果工具或参数发生变化，请重新报价。

### 同步 Similarweb 调用的幂等性

对于声明了 `Idempotency-Key` 的同步 Similarweb 路由，为每个逻辑执行生成一个唯一的 key 并与请求记录一起保存。在上述执行命令中添加此头：

```bash
--header "Idempotency-Key: ${AISA_IDEMPOTENCY_KEY:?Set AISA_IDEMPOTENCY_KEY}"
```

对已准入的请求重用 key 会返回 409，例如 `{"error":"idempotent request already admitted"}`。这可以防止重复准入；但**不会重放原始响应**。如果第一次响应丢失，请检查 Usage 和已记录的请求 ID（如有）。不要为了绕过冲突而更换 key，也不要盲目重试不确定的付费操作。全新的操作需要新的 key。异步任务和其他 API 系列有各自的约定。

对于日期输入，请遵循各个操作的约束。经典 Similarweb Traffic & Engagement 也接受完整日期，如 `2026-09-01` 到 `2026-09-30`；这不会扩展托管趋势和快照请求的 `YYYY-MM` 仅月份格式。部分校验错误包含一个 `supported` 对象，列出允许的值或范围。如有该信息请使用，但不要假设每个错误都包含此字段。

## 为智能体工作流制定预算

多步骤智能体通常产生多笔费用：检索调用、模型 token、重试或回退、对入围记录的补全，以及媒体生成。单个端点最便宜不代表整个任务最便宜——如果需要更多重试或后续调用的话。

在大规模使用前，请确定：

- 每次调用和每个任务的最大费用。在声明了最高价格支持的端点上，通过 `X-AISA-Max-Price-USD` 发送每次调用的最高价格；它会拒绝估算更高的调用，但不会限制最终费用。对于模型调用，用 `max_tokens` 限制输出。
- 智能体使用的 API key 的消费限额。
- 哪些金额需要人工确认，以及智能体是否可以回退到更贵的路由。
- 余额耗尽时的处理方式。

然后运行一个小规模的代表性任务，在 Usage 中检查记录，衡量整个工作流而非单次调用。

## 查看消费记录

[控制台 → 用量](/zh/guides/dashboard/overview#用量) 列出每个请求的端点、API key、模型、token 数和扣费金额。`GET /v1/usage` 通过代码返回某个 API key 的每日汇总，`aisa usage` 通过 CLI 实现同样功能。
