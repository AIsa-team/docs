## 什么是 AIsa？

AIsa 是 AI 智能体的资源与支付层：一个账户、一笔余额，即可发现、调用并支付实时 LLM 和媒体模型以及 100 多个数据 API——搜索、金融、社交、SEO、销售等。详见[工作原理](/zh/how-it-works)。

## AIsa 与 LLM 网关有什么区别？

LLM 网关将多个模型统一到一个 API 后面。AIsa 也做同样的事，但还加入了智能体操作所需的数据 API、MCP 服务器和 Skill 以便智能体发现并调用它们，以及按次计费与消费上限，让智能体为实际用量付费。如果你的场景只需要一个模型提供商，直接集成可能更简单；一旦智能体需要多个提供商，AIsa 就能派上用场。

## 我应该选择哪种连接方式？

- **智能体（Claude Code、Codex、Cursor 等）**：[通过 MCP 连接](/zh/agent-quickstart)。在浏览器中完成 OAuth，无需粘贴密钥。
- **希望智能体学习 AIsa 工作流：** 在此基础上添加 [智能体技能](/zh/get-started/agent-skill)。
- **不支持 MCP 的终端、脚本或 CI 任务**：[使用 CLI](/zh/get-started/cli)。
- **你自己的代码：** 通过 HTTP 使用 [API key](/zh/guides/getting-started-with-aisa)，或使用[现有 SDK](/zh/get-started/sdk-compatibility)。

## 我需要修改 OpenAI 或 Anthropic 的代码吗？

不需要。只需更改 base URL 和密钥：OpenAI SDK 使用 `https://api.aisa.one/v1`，Anthropic SDK 使用 `https://api.aisa.one`。标准参数和流式传输照常工作。详见 [OpenAI / Anthropic SDK](/zh/get-started/sdk-compatibility)。

## MCP 服务器暴露了哪些工具？

一组精简的元工具：`search` 和 `list_categories` 用于查找操作，`get_details`（也可通过 `batch_get_schema` 调用）用于获取完整契约，`batch_quote` 用于在不实际执行的情况下为调用报价，`batch_use` 用于一次执行最多 20 个调用。除 `batch_use` 外均免费；`batch_use` 按调用计费。`use` 作为已弃用的单次调用形式仍然保留。你的智能体通过这些工具访问整个数据目录，无需加载数百个工具。

## 智能体应该使用 Skill 还是直接调用 API？

如果已有 Skill 能覆盖你想要的结果，就用 Skill——它编码了要调用哪些工具、按什么顺序、以及如何呈现结果。当你的应用需要自定义编排、重试或数据处理时，直接调用 API（通过 HTTP 或 MCP `batch_use`）。两者可以结合：常规路径用 Skill，其余用直接调用。

## 用量如何计费？

模型按 token 计费；数据 API 按请求计费，要么按固定费率收费，要么根据请求返回的内容计量。所有费用从同一笔预付余额中扣除，而发现功能——文档、`/v1/models`、MCP `search`、`get_details` 和 `batch_quote`——是免费的。文档说明了计费规则但不列出价格；请查看 [aisa.one/models](https://aisa.one/models) 和 [aisa.one/api](https://aisa.one/api)，以及[计费与额度](/zh/guides/pricing)了解报价和消费上限。

## 我能限制智能体的花费吗？

可以。在控制台中为每个智能体创建独立的 API key 并设置消费限额。该限额是该 key 能花费的硬性上限。

对于单次调用，声明支持 maximum-price 的端点接受 HTTP 头 `X-AISA-Max-Price-USD`：如果成本估算超出你的上限，网关会在调用提供商之前以 `402` 拒绝请求。通过 MCP 时，先用 `batch_quote` 为调用报价，仅在报价符合预算时再用 `batch_use` 执行。两者都检查估算值，但都不会限制最终实际费用。模型路由（如 `/v1/chat/completions`）不适用此 header，因此请通过 `max_tokens` 和 key 的消费限额来约束其成本。详见[计费与额度](/zh/guides/pricing#先报价、再审核、后执行)。

## 每个端点都支持机器支付（MPP 或 x402）吗？

不是。AIsa 支持 Machine Payments Protocol（MPP），而非 x402，且仅限于部分只读数据端点。可用列表见 `https://api.aisa.one/openapi.json` 的发现文档；其他端点均需 API key。详见[机器支付](/zh/integrations/machine-payments)。

## 有哪些可用模型？

GPT、Claude、Gemini、Grok、DeepSeek、Qwen 与 Wan、Kimi、MiniMax、GLM、ByteDance Seed 与 Seedream、Hunyuan、MiMo 等，还有 embedding、图像和视频模型。目录经常更新：`GET https://api.aisa.one/v1/models` 和 [aisa.one/models](https://aisa.one/models) 始终是最新的，[模型目录](/zh/guides/models)列出了 ID 和路由。

## AIsa 会存储我的提示词或输出吗？

不会。请求内容仅做瞬时处理后即丢弃；AIsa 只保留运维元数据，如时间戳、key 标识符、token 数量、费用和状态。详见[安全与隐私](/zh/guides/security)。

## 如何开始使用？
