[AIsa 控制台](https://console.aisa.one/) 是你管理 API key 和余额、在浏览器中试用模型、审计每一次请求的地方。

| 页面 | 用途 |
| --- | --- |
| [Dashboard](https://console.aisa.one/) | 查看余额、30 天消费与请求量、错误率和模型分布 |
| [API Keys](https://console.aisa.one/api-keys) | 创建、限制、禁用和吊销 API key——参见[身份验证](/zh/guides/authentication#密钥设置) |
| [Billing](https://console.aisa.one/billing) | 充值余额——参见[计费与额度](/zh/guides/pricing) |
| [Playground](https://console.aisa.one/playground) | 向任意模型发送真实请求，并复制为 cURL |
| [Usage & Logs](https://console.aisa.one/logs) | 检查每个请求的端点、API key、模型、延迟、token、费用和状态 |

## 仪表盘

Dashboard 是控制台的首页，汇总过去 30 天的消费、流量和账户状态。

![AIsa 控制台仪表盘，展示余额与消费指标卡片、30 天消费与请求图表、模型分布及账户状态](/images/dashboard-overview.png)

**New API Key** 和 **Top Up** 按钮紧挨页面标题。如果当前有首次充值促销活动，Top Up 按钮会显示促销信息。

![四张指标卡片，分别展示总余额、30 天消费及日均值、30 天请求量及错误率、活跃 API key 数量](/images/dashboard-metrics.png)

- **Total Balance** — 可用于 API 消费的额度，随请求处理逐笔扣减。
- **Spend · 30D** — 过去 30 天的流量费用，附带日均值。
- **Requests · 30D** — 同一时间窗口内的调用次数及错误率。错误率上升通常是 API key 失效、模型不可用或请求格式错误的第一信号。
- **Active Keys** — 已启用的 API key 数（占总数比例），以及最近一次使用时间。

**Spend** 和 **Requests** 图表按天拆分同一汇总数据；悬停或使用方向键可查看单日数据。请求量持平但消费上升，通常意味着流量转向了更贵的模型或更长的上下文。**Model Split** 展示各模型的调用占比，**Account** 面板显示你的方案、验证状态和上次登录时间。

用量数据覆盖固定的 30 天窗口；余额和 API key 为实时状态。如需其他时间范围或逐请求明细，请使用 Usage & Logs。

## Playground

Playground 通过你的代码所使用的相同端点发送真实请求，并展示完整的请求体和原始响应。你至少需要一个已启用的 API key。

![AIsa Playground 左侧为请求面板，右侧为 JSON 请求预览和输出面板](/images/playground-overview.png)

1. **Key** — 选择用哪个已启用的 API key 来验证请求。完整的 key 不会发送到浏览器，用量会归属到该 key，因此使用专用 key 可将 Playground 流量与其他流量分开。
2. **Route** — **Chat completions**（`POST /v1/chat/completions`，OpenAI 兼容）或 **Messages**（`POST /v1/messages`，Anthropic 兼容）。模型列表会重新加载，因为不同路由提供的模型不同。
3. **Model** — 该 API key 在所选路由上可访问的所有模型。如果你使用的是试用额度且某个模型需要付费余额，则该模型的 Run Test 按钮会被禁用。
4. **Parameters** — Stream、Temperature（可选启用；关闭表示使用模型默认值）、Max tokens，以及 System 和 User 提示词。
5. **Run Test** — 请求进行中时变为 **Stop**。

调试面板以 **JSON** 和 **cURL** 命令（使用 `$AISA_API_KEY`）两种格式展示请求——这是将可用配置迁移到脚本中的最快方式。如果提示词包含单引号（`'`），在 shell 中执行 cURL 前请先转义。

输出面板显示提取的 **Result** 和原始 **Response**，附带延迟和 `x-request-id`。使用该 ID 可在 Usage & Logs 中定位该调用，或在联系支持时提供。Playground 请求的计费方式与 API 请求完全一致。

## Usage and Logs

Usage & Logs 是过去 30 天通过你的 API key 产生的逐请求记录。页面上所有数据均受你设置的筛选条件控制。

![AIsa 控制台 Usage & Logs 页面，展示汇总卡片、用量趋势、模型分布、筛选工具栏和逐请求日志表格](/images/logs-overview.png)

汇总卡片显示 **Requests**、**Tokens**（输入加输出）、**Cache Tokens**（读取加写入）和 **Usage Value**——按公开费率计算的流量价值——下方为实际 **charged** 金额。两者在有折扣、促销或退款时会不同。

搜索可匹配 request ID、API key、端点和模型，因此粘贴来自错误信息或 Playground 的 request ID 即可直接跳转到该调用。可按 **Stream**（流式或非流式）和 **Status**（成功、失败、已退款）筛选。

| 列 | 含义 |
| --- | --- |
| **Time** | 请求到达时间及其 request ID |
| **Endpoint** | 处理该请求的路由，例如 `/v1/chat/completions` |
| **API Key** | API key 名称，未命名则显示前缀 |
| **Model** | 处理该请求的模型 |
| **Stream** | `stream` 或 `sync` |
| **Latency** | 总耗时，附首 token 时间 |
| **Tokens** | 总量，附输入/输出拆分 |
| **Cache** | 缓存 token 总量，附读取/写入拆分 |
| **Usage Value** | 按公开费率计算的价值；如果实际收费不同，收费金额显示在下方 |
| **Status** | `success`、`failed` 或 `refunded` |

常见用法：按 Failed 筛选来调试调用；查找导致费用突增的模型和 API key；通过比较缓存读取量与总 token 来确认 prompt 缓存是否生效；审计某个 API key 的全部请求。

### 通过 API key 查询用量

`GET https://api.aisa.one/v1/usage` 默认返回已认证 API key 的汇总用量。使用发出调用的同一个 API key。该接口不是逐请求日志；如需查看单个请求，请使用上方的控制台。

```bash
# Positive Unix seconds in UTC; this example selects the last 24 hours.
start_time=$(python3 -c 'import time; print(int(time.time()) - 86400)')
curl --fail-with-body --silent --show-error --get \
  "https://api.aisa.one/v1/usage" \
  --header "Authorization: Bearer ${AISA_API_KEY:?Set AISA_API_KEY}" \
  --data-urlencode "start_time=$start_time" \
  --data-urlencode "bucket_width=1d" \
  --data-urlencode "scope=key"
```

| 参数 | 说明 |
| --- | --- |
| `start_time` | 必填，正整数 Unix 时间戳，单位为**秒**，不是毫秒或日期字符串。 |
| `end_time` | 可选，Unix 秒；默认为当前时间。必须晚于 start_time。区间包含起点、不含终点：`[start_time, end_time)`。 |
| 窗口 | 最长 **31 天**（31 × 24 小时）；更长的时段请拆分为相邻窗口。 |
| `bucket_width` | 仅支持 `1d`，按 UTC 天分桶。 |
| `scope` | 默认为 `key`。`account` 需要 OAuth 认证；普通 API key 无法请求 account 范围。 |

`totals.charged_micros_usd` 是实际收费金额；将整数微美元除以 1,000,000 即可得到美元值。`totals.usage_value_micros_usd` 是用量价值，可能与收费金额不同。对账时请确保使用相同的 API key、时间窗口和货币单位。此汇总数据不能证明特定请求的结果，也不能证明某次历史充值已成功。

## 数据加载失败时

如果余额、API key 或用量数据无法获取，Dashboard 顶部会出现一条内联警告，附带一个 **Refresh** 按钮，点击可重试加载全部数据。
