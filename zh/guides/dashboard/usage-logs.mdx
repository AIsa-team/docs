Usage Logs 页面提供账户相关活动的完整历史。它记录 API 请求、token 消耗、账单细节以及重要的系统级操作，方便你在一个地方监控用量、核对成本并审计账户事件。

这个页面适合用于：

* 追踪 API 消耗和支出
* 查看每次请求的 token 用量
* 监控请求性能
* 审计不同 group 或 API key 的活动
* 排查异常扣费或系统操作

## 记录哪些内容

Usage Logs 同时包含 API 活动和关键平台事件。

### API 请求

通过以下方式发出的请求都会被记录：

* API keys
* Playground
* LLM 推理 API
* 按次调用 API（Search、Financial、YouTube、Scholar、Twitter 等）

每次请求都会记录用量、性能和账单信息。

### 系统与账号事件

重要的账户级操作也会被记录。例如：

* 启用双因素认证
* 安全相关配置变更

这些条目会作为 system events 出现，用于审计。它们通常不会产生用量费用。

## 概览指标

页面顶部会展示所选时间范围内的汇总指标。

**Used Quota**  
显示所选时间段内消耗的总额度。

**RPM（每分钟请求数）**

表示传入请求速率。

**TPM（每分钟 Token 数）**

表示 Token 消耗速率。

这些指标有助于识别流量突增和整体用量模式。

## 筛选与搜索

Usage logs 可以通过筛选缩小结果范围。

可用筛选项包括：

* **日期和时间范围**
* **Group**
* **Token Name**
* **Model Name**

点击 **Query** 应用筛选，点击 **Reset** 清空筛选。

可以通过 **Column settings** 调整表格列的显示。

## 日志表格字段

表格中的每一行代表一个事件，可能是一次 API 请求，也可能是一次系统操作。

**Time**

事件发生的时间戳。

**Tokens**

请求使用的 API key。对于系统事件，该字段可能为空。

**Group**

API key 所属的 workspace group。

### 类型

表示请求类型。

例如：

* _**Consume**_ - 标准 API 请求，会消耗额度
* _**System**_ - 账户或平台级操作

**Model**

处理请求的模型（适用于 LLM 调用）。

**首字响应时间**

支持的 API 请求会展示性能细节，包括：

* 总请求耗时
* 首个响应 token 的时间
* 响应是否为 streaming

**Input / Output**

输入和输出 token 数量（适用于 LLM 请求）。

**Spend**

事件对应的成本：

* LLM 请求的 token-based cost
* 按次调用 API 的固定 per-call cost
* 系统事件通常无成本

**IP**

与请求相关的源 IP 地址（如果可用）。

只有当用户启用 IP 记录时，才会记录请求和错误类型日志的 IP。

**Details**

附加信息，例如应用的价格 ratio，或系统事件描述。

## 查看日志详情

点击一条日志可以展开详细拆分。

![展开的日志条目，展示详细计费明细，包括模型价格倍率、缓存命中率、Token 数量和单次请求成本计算](/images/92ad0f58-Screenshot_2026-02-13_170917.png)

展开视图包含：

### 模型倍率与缓存倍率

显示应用到该请求的模型级计费倍数。

示例字段可能包括：

* Model ratio
* Cache ratio
* Completion ratio
* Group ratio

### 计费过程

账单拆分展示成本如何计算。

它包括：

* 每 1M tokens 的 input token 价格
* 每 1M tokens 的 output token 价格
* 应用的倍数
* 最终计算出的 spend

详细公式会展示出来以保证透明度。实际账户扣费以最终计算金额为准。

### 请求路径

显示处理请求所使用的内部 API route。

示例：`/pg/chat/completions`

这有助于识别使用了哪个 endpoint。

这部分拆分可以完整说明最终成本的计算方式。

对于系统事件，展开视图会描述执行的操作。

## 账单如何体现

用量成本基于以下因素计算：

* Token 消耗（适用于 LLM APIs）
* 固定 per-call 价格（适用于非 LLM APIs）
* 适用的模型或 group 价格规则

Usage Logs 会显示每个事件的计算成本。实际账户余额扣减会反映最终计算金额。

## 实用场景

Usage Logs 页面适合用于：

* 核对每次请求的 token 消耗
* 追踪正在使用哪些模型
* 审计不同 group 的成本分布
* 调试异常计费行为
* 查看请求延迟和 streaming 性能

## 注意事项

* 所有 Playground 活动都会出现在 Usage Logs 中。
* 所有 API key 请求都会出现在 Usage Logs 中。
* 系统级操作会被记录以支持审计可见性。
* 日志中显示的成本会在适用时从账户余额中扣除。
