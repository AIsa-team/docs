**Usage & Logs** 记录最近 30 天里经过你的 AIsa 密钥的每一次请求。[Dashboard](/zh/guides/dashboard/overview) 回答的是*花了多少*，这个页面回答的是*具体哪一次请求*——端点、模型、延迟、Token、缓存命中、成本和状态，逐行呈现。

![AIsa 控制台使用日志页面，展示汇总卡片、用量价值趋势、模型占比、筛选工具栏和逐条请求日志表](/images/logs-overview.png)

入口在 [**Console → Usage & Logs**](https://console.aisa.one/logs)。页面上的所有数字都基于当前筛选条件，而不只是屏幕上可见的这几行。

## 汇总卡片

![四张汇总卡片：筛选后的请求数、Token 总数、缓存 Token 和用量价值及实际扣款](/images/logs-metrics.png)

**Requests** 是符合当前筛选条件的调用次数。

**Tokens** 是这些调用的输入加输出 Token 总数。

**Cache Tokens** 是缓存读取加写入的命中数。在支持 prompt 缓存的模型上，缓存读取数高、而 Token 数相对低，正是缓存生效的表现。

**Usage Value** 是这些流量按标准价计算的价值，下方显示实际从余额中**扣除**的金额。两者不一致，说明存在折扣、活动或退款。

## 用量价值趋势与模型占比

![用量价值趋势图，旁边是按用量价值排列的模型占比面板](/images/logs-trend.png)

**Usage Value Trend** 以 USD / 天为单位绘制窗口内的用量价值。把鼠标移到图上——或聚焦图表后用方向键——可查看任意一个点的数值，右上角的数字标注峰值。

**Model Split** 按用量价值给模型排序，最多显示 5 项。注意它是基于**当前页**的日志计算的，因此会随筛选和翻页变化，并不是整个 30 天的汇总——需要完整窗口的拆分，请看 [Dashboard](/zh/guides/dashboard/overview) 上的模型占比。

## 搜索与筛选

![工具栏包含搜索框、每页行数选择器、流式筛选和状态筛选，下方是日志表头](/images/logs-table.png)

搜索框会匹配 request ID、密钥、端点和模型——把错误响应或 [Playground](/zh/guides/dashboard/playground) 里的 request ID 粘进来，就能直接定位到那次调用。

另外三个控件用于进一步收窄结果：

* **Rows** — 每页 10、20 或 50 条
* **Stream** — 全部、流式或非流式
* **Status** — 全部、成功、失败或已退款

修改任意筛选条件都会回到第一页。

## 日志表字段

每一行对应一次 API 请求。

| 字段 | 含义 |
| --- | --- |
| **Time** | 请求到达时间，下方是 request ID |
| **Endpoint** | 处理该请求的 API 路由，例如 `/v1/chat/completions` |
| **API Key** | 使用的密钥名称；未命名时显示密钥前缀 |
| **Model** | 处理该请求的模型 |
| **Stream** | `stream`（流式）或 `sync`（同步） |
| **Latency** | 请求总耗时，下方是首 token 耗时 |
| **Tokens** | Token 总数，下方是输入 / 输出拆分 |
| **Cache** | 缓存 Token 总数，下方是读取 / 写入拆分 |
| **Usage Value** | 该次调用按标准价计算的价值；实际扣款不同时会显示在下方 |
| **Status** | `success`、`failed` 或 `refunded` |

表格底部显示当前查看的区间，并提供上一页 / 下一页控件。

如果没有匹配结果，表格会直接给出提示，而不是显示空网格——此时可以放宽筛选条件或清空搜索框。

## 典型用法

* **排查失败请求** — 筛选 Failed，拿到 request ID，与应用日志对照
* **解释成本突增** — 找出峰值当天是哪个模型和哪个密钥推高了用量价值
* **验证缓存是否生效** — 对重复 prompt 比较缓存读取数与总 Token 数
* **检查流式表现** — 筛选 Streaming，对比首 token 耗时与总延迟
* **审计密钥活动** — 搜索密钥名称，查看它在窗口内的全部调用
