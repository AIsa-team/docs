Playground 是一个交互式环境，用于在把模型集成到应用前测试 AIsa 支持的模型。你可以发送请求、调整模型参数、检查响应，并使用与生产请求相同的 API 和配置实时验证行为。

![AIsa 模型 Playground 动画演示：选择模型、输入提示词并实时查看流式响应](/images/9f5feddc-Sid_Playground.gif)

注册后即可开始使用 Playground。新账户会获得 **免费额度**，并且可以在**不生成 API key** 的情况下使用 Playground。

这个页面常用于试验不同模型、调优生成参数，并在开发过程中验证输出。

## 模型配置

左侧面板包含配置项，用于控制请求如何发送到所选模型。

![Playground 配置面板，展示模型选择器、Temperature 滑块、最大 Token 数和其他生成参数](/images/23facb9b-image.png)

可用选项会因所选模型而变化。并非所有模型都支持相同参数或输入类型。

### 分组

**Group** 选择器决定请求归属的 workspace group。Group 用于在团队或项目之间组织用量、权限和计费。

如果没有配置自定义 group，请求会使用默认 group。

### 模型

**Model** 选择器用于选择由哪个模型处理请求。这里包含来自不同 provider 的模型，全部通过同一个统一 API 访问。

切换模型不需要修改请求格式，只需要更改模型标识符。

配置项和筛选条件会根据所选模型动态更新。某个模型显示的参数，可能不适用于另一个模型。

### 自定义 Request Body 模式

启用 **Custom Request Body Mode** 后，你可以手动定义完整 JSON 请求体。对于需要直接控制 UI 中未暴露参数的高级用例，这会很有用。

关闭时，请求会根据当前选择的配置项自动生成。

### 图片 URL

**Image URLs** 选项允许你向请求附加图片 URL，从而启用多模态输入。

它适用于支持图像理解或视觉语言能力的模型。启用后，你可以提供一个或多个图片 URL，与文本 prompt 一起发送。

该选项只会在支持图像输入的模型上出现。

## 生成参数

这些控件会影响模型如何生成响应。修改会立即应用到新的请求。

可用生成参数因模型而异。

### Temperature（温度）

Temperature 控制模型输出的随机性。

较低值会生成更确定、更聚焦的响应；较高值会增加创造性和变化。

### Top P（核心采样）

Top P（nucleus sampling）会把 token 选择限制在累计概率达到指定阈值的最小集合内。

它会影响生成过程中模型词汇选择的多样性。Top P 常用于替代 temperature，或与较低 temperature 组合使用。

### 频率惩罚

Frequency Penalty 会降低响应中重复词语或短语出现的概率。值越高，越能减少生成内容中的重复。

### 存在惩罚

Presence Penalty 鼓励模型引入新概念，而不是继续围绕已有内容展开。提高这个值会让模型在长回答中更倾向探索新主题。

### 最大 Token 数

Max Tokens 设置模型在响应中最多可生成的 token 数量，用于控制响应长度和使用成本。

如果没有显式设置，会使用模型默认限制。

## 对话面板

右侧主面板是你与模型交互的区域。

* 在底部输入框输入 prompt
* 提交请求，接收所选模型的响应
* 在对话视图中查看生成结果

响应会以与 API 调用相同的形式出现，因此 Playground 很适合验证 prompt 行为和输出质量。

## 调试模式

**Show debug** 选项会展示额外的请求和响应细节。

![调试模式输出，展示原始 API 请求头、响应 Payload、Token 用量和延迟指标](/images/2f75904c-Screenshot_2026-02-12_171229.png)

其中包括原始请求 payload 和内部元数据，有助于排查异常行为或验证请求结构。

## 导入与导出

Playground 支持导入和导出配置，方便复用测试。

* **Export** 会下载当前配置和请求设置
* **Import** 会载入之前保存的配置

这适合在团队中分享测试设置，或复用常见场景。

## 用量与计费

Playground 中发出的所有请求都会计入用量和账单，与 API 请求相同。

新用户可以使用注册时提供的免费额度立即开始测试，无需创建或管理 API key。

## Playground 最适合用来做什么

Playground 适合：

* 比较不同模型的输出
* 在生产使用前调优生成参数
* 测试多模态输入
* 调试 prompt 行为
* 不写代码也能验证请求配置
