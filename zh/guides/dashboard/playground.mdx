  在集成前测试 100+ AI 模型的交互式控制台。选择 key、路由和模型，调整 stream / temperature / max tokens，并查看 AIsa 实际发送的 JSON 或 cURL 请求——使用与生产完全相同的 OpenAI 和 Anthropic 兼容 API。

Playground 是一个交互式环境，用于在把模型集成到应用之前测试 AIsa 支持的模型。它通过与生产代码相同的中转端点发送真实请求，并在结果旁边展示完整的请求体和原始响应。

![AIsa Playground 界面：左侧为请求面板，右侧为 JSON 请求预览与输出面板](/images/playground-overview.png)

入口在 [**Console → Playground**](https://console.aisa.one/playground)。请求使用你自己的 API key 发送，因此运行测试前至少需要一个**已启用的 key**。新账户会获得**免费额度**，可以直接用于 Playground（具体金额和领取条件以当时官方活动为准）。

## 端点栏

面板上方的横条显示当前配置实际请求的端点，例如 `POST https://api.aisa.one/v1/chat/completions`，右侧的 `stream: true` / `stream: false` 标签与 Stream 开关保持同步。

切换 **Route** 时，端点会随之变化。

## 请求面板

左侧面板用于定义请求。

![Playground 请求面板：Key、Route、Model 选择器，Stream、Temperature、Max tokens 控件，以及 System 和 User 提示词输入框](/images/playground-request.png)

### Key

**Key** 选择器决定使用哪个 API key 认证请求。列表只包含已启用的 key，每一项显示 key 名称以及脱敏后的前后缀。

完整 key 不会下发到浏览器，请求在后端签名。用量会记在所选 key 上，因此可以用一个专用 key 把 Playground 流量与应用流量区分开。

如果还没有已启用的 key，请先在 [API Keys](https://console.aisa.one/api-keys) 页面创建一个。

### Route

**Route** 选择器决定请求使用哪套 API：

* **Chat completions** — `POST /v1/chat/completions`，OpenAI 兼容路由。System 提示词会作为 `messages` 中的 `system` 消息发送。
* **Messages** — `POST /v1/messages`，Anthropic 兼容路由。System 提示词会作为顶层 `system` 字段发送。

切换路由会重新加载模型列表，因为两条路由暴露的模型集合不同。

### Model

**Model** 选择器列出所选 key 在当前路由下可用的全部模型。选择器下方的计数显示已加载的模型数量，刷新按钮可以重新拉取列表。

切换模型不需要改动请求格式，只有 `model` 标识符会变化。

如果账户仍在试用额度状态，而所选模型要求付费余额，Playground 会显示充值提示并禁用 **Run Test**。此时可以换一个模型，或先充值。

## 生成参数

### Stream

**Stream** 控制响应是否以 server-sent events 增量返回。开启后，输出会在 Output 面板逐 token 出现，请求体中会包含 `"stream": true`。

### Temperature

**Temperature** 是可选参数：旁边的开关决定请求中是否包含 `temperature`。开关关闭时该参数会被省略，使用模型自身的默认值。

开启后，较低的值输出更确定，较高的值变化更多。取值范围为 0–2。

### Max Tokens

**Max tokens** 设置生成 token 的上限，用于控制响应长度和成本。该参数始终包含在请求中。

### System 与 User

**System** 字段用于约束模型行为，**User** 字段则是提示词本身。两者都是纯文本输入框，编辑时请求预览会实时更新。

点击 **Run Test** 发送请求。请求进行中按钮会变为 **Stop**，点击即可立刻中断连接。

## Debug 面板

右侧面板在运行之前就能看到 AIsa 将要发送的确切内容。

![Debug 面板展示带语法高亮的 JSON 请求体，下方 Output 面板含 Result 与 Response 标签](/images/playground-debug.png)

* **JSON** — 将要提交的请求体，带行号
* **cURL** — 同一个请求的终端命令形式，使用 `$AISA_API_KEY`，可直接复制粘贴

面板右上角的复制按钮会复制当前标签页的内容。把验证好的配置从 Playground 迁到脚本或同事的终端，cURL 是最快的方式。

<Note>
  生成的命令用单引号包裹 JSON 请求体。如果 System 或 User 提示词中包含单引号（`'`），需要先转义再在 shell 中执行，否则请求体会被截断。
</Note>

## 输出面板

请求预览下方是 Output 面板。

* **Result** — 提取出的助手文本，开启 Stream 时实时流式显示
* **Response** — 响应 payload：非流式请求为完整 JSON 响应体；流式请求则按行显示每个 SSE 事件的 `data` 内容（`data:` 前缀和其他事件字段会被去掉）

底部信息行显示请求延迟（毫秒）、网关返回的 `x-request-id`，以及本次调用是否为流式。排查问题时可以用这个 request ID 去 [Usage Logs](https://console.aisa.one/logs) 页面对照，或提供给支持人员。

错误会内联显示，原始错误内容可在 **Response** 标签中查看。

## 用量与计费

Playground 的所有请求都与普通 API 请求一样计入用量和账单，并会以所选 key 的名义出现在日志和用量图表中。

## Playground 最适合用来做什么

* 不改代码就能比较不同模型的输出
* 确认某个 key 能否访问指定模型
* 在写集成代码前验证请求体
* 复制一条可用的 cURL 命令作为起点
* 在同一个界面里结合原始响应和 request ID 排查错误
