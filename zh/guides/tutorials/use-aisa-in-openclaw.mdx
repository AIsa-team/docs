OpenClaw 内置了 MCP 客户端。将 AIsa 添加为远程 MCP 服务器并完成一次登录，你的 OpenClaw 智能体即可发现并调用 AIsa 覆盖网络研究、金融、社交、SEO、销售等多个领域的能力。

AIsa MCP 服务器：

```txt
https://mcp.aisa.one/mcp
```

本指南包含两部分：

1. 添加 AIsa MCP 服务器，以便 OpenClaw 使用 AIsa 的数据和工具。
2. 可选：将 AIsa 配置为 OpenClaw 的 LLM 提供商。

## 1. 连接 AIsa 能力

### 步骤 1：添加服务器

```bash
openclaw mcp add aisa --url https://mcp.aisa.one/mcp --transport streamable-http --timeout 30 --auth oauth
```

<Note>
  请保留 `--transport streamable-http` 和 `--timeout 30`。缺少 `--transport` 时，OpenClaw 会通过 SSE 连接，服务器将返回 `405` 拒绝连接。缺少 `--timeout` 时，连接测试可能会超时。
</Note>

### 步骤 2：登录

```bash
openclaw mcp login aisa
```

OpenClaw 会输出一个授权 URL。打开该 URL，登录 AIsa 并批准访问。浏览器随后会重定向至本地回调 URL（`http://127.0.0.1:8989/oauth/callback?code=...`）；该页面可能无法加载。从地址栏复制 `code` 的值并完成登录：

```bash
openclaw mcp login aisa --code <code>
```

<Accordion title="使用 API key 替代 OAuth">
  对于无头主机（headless host），可通过 Bearer 请求头传入 API key，而不用 `--auth oauth`。单引号可防止 `${AISA_API_KEY}` 被展开，从而让 OpenClaw 保存该引用并在运行时从环境变量中读取密钥，而不是将其写入 `openclaw.json`：

  ```bash
  export AISA_API_KEY="sk-aisa-..."
  openclaw mcp add aisa --url https://mcp.aisa.one/mcp --transport streamable-http --timeout 30 \
    --header 'Authorization=Bearer ${AISA_API_KEY}'
  ```

  `AISA_API_KEY` 必须在运行 OpenClaw 的环境中设置，或者配置在 `openclaw.json` 的 `env` 块中。
</Accordion>

### 步骤 3：验证并重新加载

```bash
openclaw mcp probe
```

输出中应包含 `aisa: 7 tools`。重启网关以使运行中的智能体加载该服务器：

```bash
openclaw gateway restart
```

OpenClaw 现在已拥有 AIsa 工具。`search`、`list_categories`、`get_details`、`batch_get_schema` 和 `batch_quote`（获取具体调用的报价而不实际执行）是免费的；`use` 和 `batch_use` 会执行调用并按次计费。

尝试：

```txt
使用 AIsa 能力搜索网络并总结关于 OpenClaw 的最新信息。
```

## 2. 可选：将 AIsa 作为 LLM 提供商

OpenClaw 还可以将其智能体的 LLM 请求通过 AIsa 进行路由。直接编辑 `openclaw.json` 可以完全掌控模型配置：自定义模型列表、回退链、存储在系统钥匙串中的 auth profiles，或按渠道路由。

### 步骤 1：获取 AIsa API key

<Steps>
  <Step title="登录控制台">
    [console.aisa.one](https://console.aisa.one/)
  </Step>
  <Step title="前往 API Keys">
    [console.aisa.one/api-keys](https://console.aisa.one/api-keys)
  </Step>
  <Step title="创建新密钥">
    为其设置一个标签，例如 `openclaw-local`。立即复制该值（以 `sk-aisa-` 开头）——它只会显示一次。
  </Step>
</Steps>

### 步骤 2：设置 API key

将密钥添加到 `~/.openclaw/openclaw.json` 或在终端中导出：

```bash
export AISA_API_KEY="sk-aisa-..."
```

<Tip>
  建议优先使用环境变量，而不是将密钥硬编码到 `openclaw.json` 中。有关轮换和存储的最佳实践，请参阅[认证](/zh/guides/authentication)。
</Tip>

### 步骤 3：配置 AIsa 提供商

将以下配置块添加到 `~/.openclaw/openclaw.json`：

```json
{
  "env": {
    "AISA_API_KEY": "sk-aisa-..."
  },
  "models": {
    "mode": "merge",
    "providers": {
      "aisa": {
        "baseUrl": "https://api.aisa.one/v1",
        "apiKey": "${AISA_API_KEY}",
        "api": "openai-completions",
        "models": [
          { "id": "gpt-5.4-mini", "name": "GPT-5.4 Mini" },
          { "id": "kimi-k2.5", "name": "Kimi K2.5" },
          { "id": "claude-opus-4-8", "name": "Claude Opus 4.8" },
          { "id": "gemini-3.5-flash", "name": "Gemini 3.5 Flash" },
          { "id": "deepseek-v4.1-flash", "name": "DeepSeek V4.1 Flash" },
          { "id": "qwen3.7-max", "name": "Qwen3.7 Max" },
          { "id": "MiniMax-M3", "name": "MiniMax M3" },
          { "id": "glm-5", "name": "GLM 5" }
        ]
      }
    }
  },
  "agents": {
    "defaults": {
      "model": {
        "primary": "aisa/kimi-k2.5"
      },
      "models": {
        "aisa/kimi-k2.5": {}
      }
    }
  }
}
```

OpenClaw 现在可以识别 `aisa` 提供商。使用 `aisa/<model-id>` 格式即可引用任何模型。

### 步骤 4：重启 OpenClaw

```bash
openclaw gateway restart
```

你的智能体现在将通过 AIsa 路由请求。

## LLM 模型格式

请始终使用 `aisa/<model-id>` 格式——例如 `aisa/kimi-k2.5`、`aisa/gpt-5.4` 或 `aisa/claude-opus-4-8`。将任何受支持的模型添加到提供商配置的 `models` 数组中；完整列表请参阅[模型目录](/zh/guides/models)。

## 高级配置

### 回退链

如果主模型调用失败（由于上游服务中断或速率限制），OpenClaw 可以使用回退模型自动重试：

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "aisa/kimi-k2.5",
        "fallbacks": ["aisa/gpt-5.4-mini"]
      },
      "models": {
        "aisa/kimi-k2.5": {},
        "aisa/gpt-5.4-mini": {}
      }
    }
  }
}
```

### Auth profiles（钥匙串存储）

通过将 API key 存储在系统钥匙串中，避免将其写入 `openclaw.json`：

<Steps>
  <Step title="声明 auth profile">
    ```json
    {
      "auth": {
        "profiles": {
          "aisa:default": {
            "provider": "aisa",
            "mode": "api_key"
          }
        }
      }
    }
    ```
  </Step>
  <Step title="通过 OpenClaw CLI 存储密钥">
    ```bash
    openclaw auth set aisa:default --key "$AISA_API_KEY"
    ```
  </Step>
  <Step title="在提供商配置中引用该 profile">
    ```json
    "providers": {
      "aisa": {
        "apiKey": "auth:aisa:default",
        "baseUrl": "https://api.aisa.one/v1",
        "api": "openai-completions"
      }
    }
    ```
  </Step>
</Steps>

### 按渠道配置模型

在不同的消息平台上运行不同的模型：

```json
{
  "telegram": {
    "agents": {
      "defaults": {
        "model": { "primary": "aisa/kimi-k2.5" }
      }
    }
  },
  "discord": {
    "agents": {
      "defaults": {
        "model": { "primary": "aisa/claude-opus-4-8" }
      }
    }
  }
}
```

## 故障排除

<AccordionGroup>

<Accordion title="'No API key found for provider aisa'">
**解决方法**：
1. 确认已设置 `AISA_API_KEY`：`echo $AISA_API_KEY`
2. 确认 `openclaw.json` 引用的是 `${AISA_API_KEY}`（而非字面量字符串）。
3. 重启 OpenClaw，使其重新读取环境变量。
4. 作为最后手段，可先硬编码密钥以确认其余配置正常，然后再将其移回环境变量中。
</Accordion>

<Accordion title="认证错误（401 / 403）">
**解决方法**：
1. 在[控制台](https://console.aisa.one)中确认密钥有效。
2. 确保 `baseUrl` 完全为 `https://api.aisa.one/v1`（末尾不能有斜杠）。
3. 有关轮换指南，请参阅[认证](/zh/guides/authentication)。
</Accordion>

<Accordion title="模型无法正常工作">
**解决方法**：
1. 对照[模型目录](/zh/guides/models)仔细核对模型 ID。
2. 确保该模型已列在 `models.providers.aisa.models` 中。
3. 以 `aisa/<model-id>` 格式引用该模型。
</Accordion>

<Accordion title="AIsa 工具缺失">
**解决方法**：
1. 运行 `openclaw mcp list`，确认 **aisa** 已配置为 `streamable-http`。
2. 运行 `openclaw mcp status --verbose` 检查登录状态；如有需要，再次运行 `openclaw mcp login aisa`。
3. 运行 `openclaw gateway restart`，以便运行中的智能体重新加载服务器。
</Accordion>

<Accordion title="'SSE error: Non-200 status code (405)' 或 'Request timed out'">
**解决方法**：`openclaw mcp add` 会在保存前测试连接，因此添加失败时不会保存任何内容。请使用 `--transport streamable-http --timeout 30` 重新运行该命令。若要替换已有条目，请先运行 `openclaw mcp unset aisa`。
</Accordion>

<Accordion title="'Blocked: resolves to private/internal/special-use IP address'">
**解决方法**：OpenClaw 会拦截解析为私有或专用地址的主机。处于 fake-IP 模式的代理（例如 Clash 或 Surge）可能会导致 `clerk.aisa.one` 解析为此类地址。请在 fake-IP 中将 `aisa.one` 排除，或者使用 API key 选项替代 OAuth。
</Accordion>

</AccordionGroup>
