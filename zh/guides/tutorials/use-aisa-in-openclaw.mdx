OpenClaw 内置了 MCP 客户端。将 AIsa 添加为远程 MCP 服务器并完成一次登录后，你的 OpenClaw 智能体即可发现并调用 AIsa 在网络调研、金融、社交、SEO、销售等多个领域的各种能力。

AIsa MCP 服务器：

```txt
https://mcp.aisa.one/mcp
```

本指南包含两部分：

1. 添加 AIsa MCP 服务器，以便 OpenClaw 使用 AIsa 的数据与工具。
2. 可选：将 AIsa 配置为 OpenClaw 的 LLM 提供商。

## 1. 连接 AIsa 能力

### 步骤 1：添加服务器

```bash
openclaw mcp add aisa --url https://mcp.aisa.one/mcp --transport streamable-http --timeout 30 --auth oauth
```

<Note>
  请保留 `--transport streamable-http` 和 `--timeout 30`。如果不指定 `--transport`，OpenClaw 会通过 SSE 连接，服务器将返回 `405` 拒绝连接；如果不指定 `--timeout`，连接测试可能会超时。
</Note>

### 步骤 2：登录

```bash
openclaw mcp login aisa
```

OpenClaw 会输出一个授权 URL。打开该链接，登录 AIsa 并批准访问。随后浏览器会重定向到一个本地回调 URL（`http://127.0.0.1:8989/oauth/callback?code=...`）；该页面可能无法加载。从地址栏复制 `code` 的值，并完成登录：

```bash
openclaw mcp login aisa --code <code>
```

<Accordion title="使用 API key 替代 OAuth">
  对于无头主机（headless host），可以将 API key 作为 Bearer 请求头传入，而不使用 `--auth oauth`。单引号可防止 `${AISA_API_KEY}` 被展开，从而让 OpenClaw 保存该引用并在运行时从环境中读取密钥，而不是将其写入 `openclaw.json`：

  ```bash
  export AISA_API_KEY="sk-aisa-..."
  openclaw mcp add aisa --url https://mcp.aisa.one/mcp --transport streamable-http --timeout 30 \
    --header 'Authorization=Bearer ${AISA_API_KEY}'
  ```

  `AISA_API_KEY` 必须在运行 OpenClaw 的环境中设置，或者在 `openclaw.json` 的 `env` 块中配置。
</Accordion>

### 步骤 3：验证并重新加载

```bash
openclaw mcp probe
```

输出应包含 `aisa: 7 tools`。重启网关，以便运行中的智能体能加载该服务器：

```bash
openclaw gateway restart
```

OpenClaw 现在已拥有 AIsa 工具。`search`、`list_categories`、`get_details`、`batch_get_schema` 以及 `batch_quote`（对具体调用进行报价而不实际执行）均免费；`use` 和 `batch_use` 会执行调用并按次计费。

尝试：

```txt
使用 AIsa 能力搜索网络并总结关于 OpenClaw 的最新信息。
```

## 2. 可选：将 AIsa 用作 LLM 提供商

OpenClaw 还可以将其智能体的 LLM 请求通过 AIsa 进行路由。直接编辑 `openclaw.json` 即可完全控制模型配置：自定义模型列表、回退链、OpenClaw 认证存储库中的凭据或按频道路由。

### 步骤 1：获取你的 AIsa API key

<Steps>
  <Step title="登录控制台">
    [console.aisa.one](https://console.aisa.one/)
  </Step>
  <Step title="前往 API Keys">
    [控制台 → API Keys](https://console.aisa.one/api-keys)
  </Step>
  <Step title="创建新密钥">
    为其添加诸如 `openclaw-local` 的标签。立即复制该值（以 `sk-aisa-` 开头）——它只显示一次。
  </Step>
</Steps>

### 步骤 2：设置你的 API key

将密钥添加到 `~/.openclaw/openclaw.json`，或在 Shell 中导出环境变量：

```bash
export AISA_API_KEY="sk-aisa-..."
```

<Tip>
  相比于在 `openclaw.json` 中硬编码密钥，建议优先使用环境变量。有关轮换和存储的最佳实践，请参阅[认证](/zh/guides/authentication)。
</Tip>

### 步骤 3：配置 AIsa 提供商

将以下代码块添加到你的 `~/.openclaw/openclaw.json` 中：

```json
{
  "env": {
    "AISA_API_KEY": "sk-aisa-..."
  },
  "models": {
    "mode": "merge",
    "providers": {
      "aisa": {
        "baseUrl": "https://api.aisa.one/v1",
        "apiKey": "${AISA_API_KEY}",
        "api": "openai-completions",
        "models": [
          { "id": "gpt-5.4-mini", "name": "GPT-5.4 Mini" },
          { "id": "kimi-k2.5", "name": "Kimi K2.5" },
          { "id": "claude-opus-4-8", "name": "Claude Opus 4.8" },
          { "id": "gemini-3.8-flash", "name": "Gemini 3.8 Flash" },
          { "id": "deepseek-v4.1-flash", "name": "DeepSeek V4.1 Flash" },
          { "id": "qwen3.7-max", "name": "Qwen3.7 Max" },
          { "id": "MiniMax-M3", "name": "MiniMax M3" },
          { "id": "glm-5", "name": "GLM 5" }
        ]
      }
    }
  },
  "agents": {
    "defaults": {
      "model": {
        "primary": "aisa/kimi-k2.5"
      },
      "models": {
        "aisa/kimi-k2.5": {}
      }
    }
  }
}
```

OpenClaw 现在已能识别 `aisa` 提供商。使用 `aisa/<model-id>` 格式引用任意模型。

### 步骤 4：重启 OpenClaw

```bash
openclaw gateway restart
```

你的智能体现在将通过 AIsa 路由请求。

## LLM 模型格式

请始终使用 `aisa/<model-id>` 格式——例如 `aisa/kimi-k2.5`、`aisa/gpt-5.4` 或 `aisa/claude-opus-4-8`。将任意受支持的模型添加到提供商配置中的 `models` 数组中；完整列表请参阅[模型目录](/zh/guides/models)。

## 高级配置

### 回退链

如果主要模型发生故障（由于上游服务中断或速率限制），OpenClaw 可以使用回退模型自动重试：

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "aisa/kimi-k2.5",
        "fallbacks": ["aisa/gpt-5.4-mini"]
      },
      "models": {
        "aisa/kimi-k2.5": {},
        "aisa/gpt-5.4-mini": {}
      }
    }
  }
}
```

### 将密钥保存在 OpenClaw 的认证存储库中

将 API key 保存在 OpenClaw 本地认证存储库中，避免写入 `openclaw.json`：

```bash
printf "%s\n" "$AISA_API_KEY" | openclaw models auth paste-api-key --provider aisa
```

密钥保存在 `aisa:manual` profile 下（传入 `--profile-id` 可指定其他名称）。OpenClaw 会从认证存储库解析凭据，因此你可以从 `models.providers.aisa` 中移除 `apiKey`。

### 按频道配置模型

在特定聊天中运行不同的模型。`channels.modelByChannel.<platform>` 下的键是该平台上的频道或群组 ID；值为 `aisa/<model-id>`：

```json
{
  "channels": {
    "modelByChannel": {
      "telegram": {
        "-1001234567890": "aisa/kimi-k2.5"
      },
      "discord": {
        "123456789012345678": "aisa/claude-opus-4-8"
      }
    }
  }
}
```

OpenClaw 对 `openclaw.json` 进行严格验证：诸如 `telegram` 或 `discord` 等未知的顶层键会导致 Gateway 拒绝启动。

## 监控用量

在 [AIsa 控制台](https://console.aisa.one)中跟踪你的用量和每次请求的详细信息。有关可用指标与日志，请参阅[用量](/zh/guides/dashboard/overview#用量)。

## 故障排查

<AccordionGroup>

<Accordion title="'No API key found for provider aisa'">
**解决方案**：
1. 确认已设置 `AISA_API_KEY`：`echo $AISA_API_KEY`
2. 确认 `openclaw.json` 引用了 `${AISA_API_KEY}`（而非字面量字符串）。
3. 重启 OpenClaw 以使其重新读取环境变量。
4. 作为最后手段，可先硬编码密钥以确认其余配置正常工作，然后再将其移回环境变量。
</Accordion>

<Accordion title="认证错误 (401 / 403)">
**解决方案**：
1. 在[控制台](https://console.aisa.one)确认密钥有效。
2. 确保 `baseUrl` 严格为 `https://api.aisa.one/v1`（末尾不带斜杠）。
3. 有关轮换指南，请参阅[认证](/zh/guides/authentication)。
</Accordion>

<Accordion title="模型无法工作">
**解决方案**：
1. 对照[模型目录](/zh/guides/models)仔细核对模型 ID。
2. 确保该模型已在 `models.providers.aisa.models` 中列出。
3. 使用 `aisa/<model-id>` 格式引用它。
</Accordion>

<Accordion title="AIsa 工具缺失">
**解决方案**：
1. 运行 `openclaw mcp list` 并确认 **aisa** 已配置为 `streamable-http`。
2. 运行 `openclaw mcp status --verbose` 检查登录状态；如有必要，重新运行 `openclaw mcp login aisa`。
3. 运行 `openclaw gateway restart`，以便运行中的智能体重新加载该服务器。
</Accordion>

<Accordion title="'SSE error: Non-200 status code (405)' 或 'Request timed out'">
**解决方案**：`openclaw mcp add` 在保存前会测试连接，因此添加失败不会保存任何内容。请使用 `--transport streamable-http --timeout 30` 再次运行。若要替换已有条目，请先运行 `openclaw mcp unset aisa`。
</Accordion>

<Accordion title="'Blocked: resolves to private/internal/special-use IP address'">
**解决方案**：OpenClaw 会拦截解析到私有或特殊用途地址的主机。处于 fake-IP 模式的代理（例如 Clash 或 Surge）可能会导致 `clerk.aisa.one` 解析成此类地址。请在 fake-IP 中将 `aisa.one` 排除，或使用 API key 方案替代 OAuth。
</Accordion>

</AccordionGroup>
