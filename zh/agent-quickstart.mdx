---
title: "把 Agent 连接到 AIsa"
description: "优先用 MCP OAuth 接入；只有 MCP 跑不起来时才用 CLI。"
---

配置 AIsa。匹配的命令由你自己执行，不要让用户去跑。

若已有可用连接，直接复用：官方 `aisa` Skill 加上有效的 CLI 认证，或已具备 `AISA_SEARCH_TOOL`、`AISA_BATCH_GET_SCHEMA`、`AISA_BATCH_QUOTE`、`AISA_BATCH_USE` 的统一 MCP。用户明确的传输选择或仍有效的已授权连接优先；不要自动迁移或重装。不要改无关模型设置。安装和凭证按当前 Agent 环境描述。

只要当前客户端能添加 MCP 连接器，无论用户本机还是云端、有没有终端，都默认使用原生远程 MCP `https://tools.aisa.one/mcp`（Streamable HTTP，OAuth）。可用的 shell 不是选择 CLI 的理由。

仅当当前客户端完全没有 MCP 机制、任务是持有既有 key 且无法完成 OAuth 的非交互自动化（CI、cron、脚本），或用户明确选择 CLI 时，才使用 CLI。上述门槛与下文的 Node 规则优先于任何已安装的 `aisa` Skill；Skill 只承接后续操作。

## MCP（默认）

连接 `https://tools.aisa.one/mcp`（Streamable HTTP，OAuth）。不需要安装 CLI、npm、npx 或 Skill；已安装的指引仍可使用。由客户端完成浏览器登录并保存 token。不要使用 `https://mcp.aisa.one/servers` 或默认 `aisa connect` 的 web-search。

通过客户端的原生 MCP 配置添加连接器，然后让用户在浏览器完成 OAuth。如果客户端支持 MCP 但你在这里加不了连接器——能力未知、沙盒或权限拒绝——不要改走 CLI：请用户启用或添加连接器，然后等待。如果客户端需要重载或新开会话才能加载连接器，告诉用户；之后验证四个工具都在，期间不要改走 CLI。

Grok Bot + Plugins：Settings → Plugins → Add → 如需则认证 → `@` 附加。若有原生自定义 MCP 设置，填入该 URL 并完成 OAuth。两者都不可用时，请用户启用或添加该连接器。grok.com（`grok.com/connectors`）是另一款产品。

随后使用上面四个工具：search → `has_full_schema` 为 false 时 schema → quote → use，且须在已授权范围和额度内。工具 ID 和参数来自 search/schema；不要编造 ID 或价格。Quote 不执行，也不等于批准执行。缺失、失败或部分 quote 不是免费，也不是整批总额或上限。预估费用不是上限。工具、参数或范围变化时重新 quote。如果 quote 或已记录的最高费用超过剩余已批准额度，就停止。

## CLI（仅当 MCP 跑不起来）

门槛：当前客户端没有 MCP 机制、任务是持有既有 key 的非交互自动化，或用户明确选择 CLI。Node.js **必须已经安装**——否则停下；客户端有 MCP 就用 MCP，没有就告诉用户缺 Node.js。不要绕过缺失的前置条件或被拒的写入：不安装 Node/npm，不建私有或隔离运行时，不重定向 `HOME`。

```sh
npx skills add AIsa-team/agent-skills --skill aisa --agent codex --global
```

把 `--agent` 改成当前 harness（`codex`、`claude-code`、`cursor` 等）。个人通用接入建议 `--global`，除非用户要求限制在当前仓库。不要使用 `--all` 或 `*`。需要 Node.js **22.20.0+**（`skills` 1.5.25 的 `engines`）。

如果 `npx skills` 跑不起来且上面的门槛仍成立，先阅读 [Agent 快速开始回退](https://aisa.one/docs/zh/agent-quickstart-fallbacks.md) 的 Skill 下载节，再执行该节。

```sh
npm install -g @aisa-one/cli
aisa --version
```

复用已经能用的 `@aisa-one/cli` **0.5.0 或更高**；只有缺失时才安装；不要降级。CLI 仍可沿用 Node.js **18+**。Skill 落盘后读取它。登录遵循该 Skill 和 `aisa login --help`。用 `aisa balance` 证明认证。`aisa whoami` 只检查本地。`AISA_API_KEY` 优先于已存储密钥；冲突时说明两个来源。不要打印凭证，也不要让用户去控制台复制 Key。交互场景以浏览器 `aisa login` 为主获取凭证；无头自动化使用预先配置的 `AISA_API_KEY`。

## 收口

只有 MCP 路径上 OAuth 完成且上面四个工具都在，或 CLI 路径上的 `aisa balance`，才报告 **AIsa is connected.** metadata 或 `401` 不是受保护调用。连接器加不上就不是已连接。用户已点名任务就继续，否则询问 **What would you like to do first?** CLI 路径遵循 `aisa` Skill；MCP 路径使用上面四个工具。接入不是消费批准。

不要为了绕过缺凭证、额度用尽或同一 API 故障而跳到 HTTP。不要用付费请求探测可用性。不要提取客户端持有的 MCP OAuth token。

仅当 CLI 和 MCP 都不可用、能发 HTTP、且已有有效的 AIsa key 时：先读完 [Agent 快速开始回退](https://aisa.one/docs/zh/agent-quickstart-fallbacks.md) 的直接 HTTP 节（含 endpoint 文档、计价和批准 XML），再提出付费方案或费用批准，也再发起任何付费请求。模型、REST、Key 或额外 Skill：[AIsa 文档](https://aisa.one/docs/zh/guides)。
