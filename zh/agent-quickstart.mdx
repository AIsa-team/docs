目标：让 Agent 走到**最小且可验证**的下一步，而不是一次性加载完整文档索引。

## 重要：付费和高成本 API 的先批准后执行合同

该合同适用于每一个付费、动态计价或可能高成本的 API endpoint，无论它是直接调用、通过 Agent Skill，还是通过 MCP 数据工具调用。

```xml
<IMPORTANT id="paid-api-approval-first">
  <before-paid-data-call>
    docs、/v1/models、capability 或 MCP discovery，以及成本 quote 可在批准前使用。
    估价时：对准备执行的原请求原样发送，并加上请求头 X-AISA-Cost-Mode: quote。不要执行数据调用。
    不要自己用 x-aisa-pricing 计算 USD。
    quote 返回 object=cost_estimate。USD = estimated_cost_micros_usd / 1000000。
    若存在 max_cost_micros_usd，那才是已记录的最高费用。
    停止：用户要求收集、调研或输出数据，不等于批准。必须说出精确 endpoint 与 scope、quote 得到的 USD、以及 may_exceed_estimate 是否为 true，然后等待用户在下一条消息中明确批准该 scope 与上限。
    预批准的有界请求：若用户当前消息已明确批准单个数据项并给出明确的 USD 上限，则对该请求原样 quote；若 quote 的 USD 不超过该上限，无需再次询问，直接执行这一笔，之后任何付费数据仍需先问。若 quote 超过上限或 scope 不明确，不得执行；泛泛的“帮我查一下”不构成预批准。
    若 may_exceed_estimate 为 true 且没有 max_cost_micros_usd，即没有已记录上限：不得执行该请求，必须说明没有已记录的最大费用。有界替代方案是新的 scope，需要新的批准。示例或用户给出的预算都不是可执行上限。
    若 quote 的 USD 超过用户给出的预算，不得执行；说明报价超出预算并等待。
  </before-paid-data-call>
  <prohibited>
    不得在规划的同一轮调用付费数据 API，不得把初始请求当作同意，也不得为了价格发现、"probe"、"test" 或“先探一下”而调用付费 endpoint。
  </prohibited>
  <after-approval>
    只能执行已批准的请求，且不要带 quote 头。如果 endpoint、scope 或最高费用变化，必须重新 quote 并取得新的明确批准。
  </after-approval>
</IMPORTANT>
```

**典型场景 — SimilarWeb：** 对准备执行的请求加 `X-AISA-Cost-Mode: quote` 拿到 USD，再据此请求批准。不要自己根据 [`x-aisa-pricing`](https://aisa.one/openapi.yaml) 心算。若用户已批准 0.10 美元的单月 visits 预览：quote Traffic & Engagement（`metrics=visits`、一个月），quote 不超过 0.10 美元就直接执行这一笔，之后再问。不要用 snapshot。若 snapshot 的 quote 没有 `max_cost_micros_usd`，不得执行。

## 最小设置事实

AIsa 提供两类端点：

| 用途 | 端点 |
| --- | --- |
| OpenAI 兼容聊天、模型路由、SDK | `https://api.aisa.one/v1` |
| AIsa 数据 API 与非聊天能力 API | `https://api.aisa.one/apis/v1` |

大多数模型客户端只需要：

```txt
base_url: https://api.aisa.one/v1
api_key:  $AISA_API_KEY
```

API key 作为 Bearer token 使用。不要打印、记录、提交或硬编码密钥。优先使用环境变量或 Agent runtime 的 secret store。

```bash
export AISA_API_KEY="YOUR_AISA_API_KEY"
```

如果用户还没有提供 key，请说明到哪里创建，而不是编造一个看似真实的占位值。

请选择当前模型支持的 endpoint。通过[模型目录](/zh/guides/models)或对应 API reference 确认，不要根据模型名称猜测应使用 `chat/completions`、`responses`、`messages` 还是媒体 endpoint。

## Agent 行为准则

- 只有目标路径不清楚时，才问一个澄清问题。
- 只加载完成任务所需的最小文档集合。
- 不要打开无关 API 页面。
- 简短总结和链接足够时，不要把大段文档粘贴进对话。
- 让所选模型与有明确记录的 endpoint 匹配，不要根据名称推断路由支持情况。
- 修改文件、安装软件或发送计费请求前，先说明操作并获得用户确认。
- 声称配置可用前，完成下面对应的检查。
- 对于密钥，只验证存储方式，不展示密钥本身。

## 验证设置

先通过只读请求检查网络和认证，不调用模型：

```bash
curl --silent --show-error --fail \
  --output /dev/null \
  --write-out "HTTP %{http_code}\n" \
  https://api.aisa.one/v1/models \
  -H "Authorization: Bearer $AISA_API_KEY"
```

`HTTP 200` 表示 API 已接受该 key 并返回模型目录。`401` 或 `403` 表示认证或访问权限存在问题。此检查不能证明某个具体模型支持客户端使用的请求协议。

用户选定模型并同意可能产生费用的请求后，再执行对应 API reference 中最小的示例请求。不要仅根据文档就声称设置已经可用。

## 研究任务的证据规则

本快速开始是路由摘要，不是精确请求 schema、当前模型可用性、价格或服务状态的权威来源。请通过链接的 API reference、实时目录或运行结果核实这些信息。

```txt
搜索结果是发现线索。
抓取的来源页面是待评估的证据。
生成摘要是综合判断，不是证据。
```

抓取页面只能证明该来源表达了什么。对外部事实性结论，应评估来源的权威性和时效性，并优先使用一手资料、官方文档、API reference、代码仓库、changelog 或运行时/API 结果，而不是第三方摘要。
