---
title: "把 Agent 连接到 AIsa"
description: "安装 AIsa Skill，登录，然后开始使用工具。"
---

配置 AIsa。匹配的命令由你自己执行，不要让用户去跑。

若已有可用连接，直接复用：官方 `aisa` Skill 加上有效的 CLI 认证，或已具备 `AISA_SEARCH_TOOL`、`AISA_BATCH_GET_SCHEMA`、`AISA_BATCH_QUOTE`、`AISA_BATCH_USE` 的统一 MCP。用户明确的传输选择或仍有效的已授权连接优先；不要自动迁移或重装。不要改无关模型设置。安装和凭证按当前 Agent 环境描述。

按 Agent **实际执行位置**选择路径，不要只看产品名，也不要只看有没有终端。

- 用户本机：优先一个官方 `aisa` Skill 加上 CLI。本机任意可用 shell 都可以，包括 PowerShell。
- Grok Bot 或其他云端沙箱，即使有终端：优先原生远程 MCP `https://tools.aisa.one/mcp`。云端终端不是用户本机。

## 本机

```sh
npx skills add AIsa-team/agent-skills --skill aisa --agent codex --global
```

把 `--agent` 改成当前 harness（`codex`、`claude-code`、`cursor` 等）。个人通用接入建议 `--global`，除非用户要求限制在当前仓库。不要使用 `--all` 或 `*`。需要 Node.js **22.20.0+**（`skills` 1.5.25 的 `engines`）。

如果 Node 或 `npx skills` 跑不起来，且当前是用户本机，**或**用户在此环境明确要求 CLI/Skill（包括云端沙箱），先阅读 [Agent 快速开始回退](https://aisa.one/docs/zh/agent-quickstart-fallbacks.md) 的 Skill 下载节，再执行该节。

```sh
npm install -g @aisa-one/cli
aisa --version
```

复用已经能用的 `@aisa-one/cli` **0.5.0 或更高**；只有缺失时才安装；不要降级。CLI 仍可沿用 Node.js **18+**。Skill 落盘后读取它。登录遵循该 Skill 和 `aisa login --help`。用 `aisa balance` 证明认证。`aisa whoami` 可能刷新已存 token，但不是受保护认证证明。`AISA_API_KEY` 覆盖已存 CLI 凭证且不会刷新；冲突时说明两个来源。不要打印凭证、不要读 token 文件，也不要让用户去控制台复制 Key。获取凭证仍以浏览器 `aisa login` 为主。

## 云端

连接 `https://tools.aisa.one/mcp`（Streamable HTTP，OAuth）。不需要安装 CLI、npm、npx 或 Skill；已安装的指引仍可使用。由客户端完成浏览器登录并保存 token。不要使用 `https://mcp.aisa.one/servers` 或默认 `aisa connect` 的 web-search。

Grok Bot + Plugins：Settings → Plugins → Add → 如需则认证 → `@` 附加。若有原生自定义 MCP 设置，填入该 URL 并完成 OAuth。两者都不可用时，请用户启用或添加该连接器。grok.com（`grok.com/connectors`）是另一款产品。

随后使用上面四个工具：search → `has_full_schema` 为 false 时 schema → quote → use，且须在已授权范围和额度内。工具 ID 和参数来自 search/schema；不要编造 ID 或价格。Quote 不执行，也不等于批准执行。缺失、失败或部分 quote 不是免费，也不是整批总额或上限。预估费用不是上限。工具、参数或范围变化时重新 quote。如果 quote 或已记录的最高费用超过剩余已批准额度，就停止。

## 收口

只有 CLI 路径上的 `aisa balance`，或 MCP 路径上 OAuth 完成且上面四个工具都在，才报告 **AIsa is connected.** metadata 或 `401` 不是受保护调用。连接器加不上就不是已连接。用户已点名任务就继续，否则询问 **What would you like to do first?** CLI 路径遵循 `aisa` Skill；MCP 路径使用上面四个工具。接入不是消费批准。

不要为了绕过缺凭证、额度用尽或同一 API 故障而跳到 HTTP。不要用付费请求探测可用性。不要提取客户端持有的 MCP OAuth token。

仅当 CLI 不可用、MCP 不可用、能发 HTTP，且静态 `AISA_API_KEY` 或等效秘密已经单独配置好时：先读完 [Agent 快速开始回退](https://aisa.one/docs/zh/agent-quickstart-fallbacks.md) 的直接 HTTP 节（含 endpoint 文档、计价和批准 XML），再提出付费方案或费用批准，也再发起任何付费请求。浏览器 OAuth 不会生成该静态 key。模型、REST、Key 或额外 Skill：[AIsa 文档](https://aisa.one/docs/zh/guides)。
