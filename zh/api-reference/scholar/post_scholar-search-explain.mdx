对一份已经取回的检索结果做解释。和那三个搜索端点不同，这个接收 **JSON 请求体**：`search_id`（必填 —— 由 [`post_scholar_search_web`](/zh/api-reference/scholar/post_scholar-search-web)、[`post_scholar_search_scholar`](/zh/api-reference/scholar/post_scholar-search-scholar) 或 [`post_scholar_search_mixed`](/zh/api-reference/scholar/post_scholar-search-mixed) 返回的 `id`），以及 `detail_level`（BRIEF / MODERATE / DETAILED）、`language`、`response_mode`。⚠️ 请用 `response_mode: NON_STREAMING`，它返回 `{"message": "…"}` 这样的 JSON，实测约 2 KB。COMPLETE 与 INCREMENTAL 模式发的是 server-sent events，而**每个事件都会重复到目前为止的整段答案** —— 同一份解释那样返回实测 177 KB，大约 90 倍，何况一次工具调用本来也没法增量消费流式响应。它只能解释已有的检索，不能自己发起检索。
