某个已爬取 `url` 的加载时间线——请求了什么、按什么顺序、各花多久。实测 835 字节。读的是一次已完成的爬取，因此需要 `post_dataforseo_on_page_submit` 返回的 `id`，并会带回 `crawl_progress` 和 `crawl_status`（`max_crawl_pages`、`pages_in_queue`、`pages_crawled`）——结果偏少时先看这几个字段，爬取还在跑就是本来没那么多。 用它解释页面为什么慢；要带评分的性能审计改用 `post_dataforseo_on_page_lighthouse_live_json`。## 示例
