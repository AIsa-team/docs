## 面临的问题

销售与商务拓展团队通常需要花费数小时来建立目标客户名单、寻找合适的联系人，并挖掘恰当的触达理由。智能体可以承担前期的调研工作，但 enrichment 会产生费用并返回个人数据，且 CRM 写入或外发触达操作会在现实中产生实际影响。一个理想的工作成果应包含一份精简且经过评分的目标企业与联系人列表，附带来源链接和触发事件，以及消息沟通草稿；但在你批准之前，绝不执行任何写入或发送操作。

## 提示词

在 AIsa [通过 MCP 连接](/zh/agent-quickstart)后，将以下内容提供给你的智能体：

```txt wrap
使用 AIsa 查找符合以下条件的 <N> 个目标客户：<行业>、<员工规模范围>、<地区>、<技术栈或特征信号>。
使用 `search` 查找合适的 AIsa 工具，并用 `batch_quote` 获取付费调用的报价。在执行任何付费调用前务必向我确认，尤其是在 enrichment 之前。
步骤 1：按条件搜索公司和人员（暂不执行 enrichment）。步骤 2：拉取每个客户的最新动态以寻找触发事件。步骤 3：根据我的标准为每个客户打分并展示评分详情。
仅在我批准精选名单后，才对这些人员执行 enrichment，且仅请求姓名、职位和工作邮箱。
返回表格：目标客户 | 匹配原因 | 触发事件（附链接与日期） | 联系人角色 | 缺失或存疑字段。然后为每个客户撰写一段 3 句话的破冰沟通草稿。
不要创建联系人，不要将任何人添加到 sequence，也不要发送邮件。
```

## 使用的 API 与 Skill

通过 MCP，你的智能体可以通过 `https://mcp.aisa.one/mcp` 上的几个元工具调用这些能力：`search`、`list_categories`、`get_details` 和 `batch_quote` 免费；`batch_use`（单次最多 20 个调用）按次计费。

| 步骤 | 智能体调用内容 | 参考文档 |
| --- | --- | --- |
| 构建目标名单 | 按员工人数、行业、地区、技术栈搜索公司 | [Organization Search](/zh/api-reference/apollo/post_apollo-mixed-companies-search) |
| 寻找人员 | 人员搜索（隐藏联系方式） | [People API Search](/zh/api-reference/apollo/post_apollo-mixed-people-api-search) |
| 触发事件 | 按分类和日期搜索公司新闻 | [News Articles Search](/zh/api-reference/apollo/post_apollo-news-articles-search) |
| 公司背景信息 | 网站流量快照 | [Website Traffic Snapshot](/zh/api-reference/similarweb/get_similarweb-website-traffic-snapshot), [Use Similarweb](/zh/agent-skills/use-similarweb) |
| 丰富入围名单信息 | 按域名丰富单家公司；按标识符丰富单个人员 | [Organization Enrichment](/zh/api-reference/apollo/get_apollo-organizations-enrich), [People Enrichment](/zh/api-reference/apollo/post_apollo-people-match) |
| 创作者目标 | 针对红人营销计划的创作者发现 | [KOL Creator Discovery](/zh/agent-skills/kol-creator-discovery) |
| 写入操作（受控门禁） | 创建联系人；添加到 sequence | [Create a Contact](/zh/api-reference/apollo/post_apollo-contacts), [Add Contacts to a Sequence](/zh/api-reference/apollo/post_apollo-emailer-campaigns-sequence-id-add-contact-ids) |

People search 会提示是否存在匹配项，并标记是否有可用的邮箱或电话号码；enrichment 则会展示具体详细信息，且 enrichment 费用在此环节产生。获取个人邮箱或电话号码属于可选（opt-in）项目，需额外计费。

| 目标客户 | 匹配原因 | 触发事件 | 联系人角色 | 缺失 / 存疑信息 |
| --- | --- | --- | --- | --- |
| Example Corp | 200–500 名员工，欧洲，使用 ExampleDB | 开设新办公室，2026-01-08（[链接](https://example.com/news)） | Head of Data | 工作邮箱尚未 enrich |
| Sample Labs Inc. | 50–200 名员工，欧洲，正在招聘数据岗位 | 融资公告，2025-12-20（[链接](https://example.org/press)） | VP Engineering | 员工规模来源为一个区间 |

**评分**：符合匹配标准（4/5、3/5），按客户分别展示。**破冰草稿（Example Corp）**：“祝贺开设新办公室……”

## 安全护栏

- **先只读，后 enrich**。广泛检索，仅对获批的精选名单执行 enrichment。切勿默认对每个结果都执行 enrichment。
- **数据最小化**。仅请求工作流必需的字段；记录数据来源与获取时间；并遵守相关的隐私、用户授权与触达规则。
- **评分过程可审查**。将原始数据、衍生评分、模型解释与缺失字段明确分开。模型绝不可凭空捏造营收、员工规模、职位头衔、联系方式或购买意向。
- **起草不等于发送**。在创建联系人、将人员添加到 sequence、发送消息或更新 CRM 之前：必须核对已连接的账户与权限，展示确切的操作及目标对象，获得明确批准，仅执行一次，并校验执行结果。只读访问权限并不代表拥有写入权限。
- **先报价，再询问**。通过 `batch_quote` 获取免费报价，且仅在获得批准后才使用 `batch_use` 执行相同调用。报价检查的是费用预估，而非最终扣费。参见 [计费与额度](/zh/guides/pricing)。
- **何时可能不需要 AIsa**：如果你仅使用单一数据服务商，且已经拥有成熟稳定的 enrichment、用户授权和触达流程，那么直接集成 CRM 或数据服务商会更加简单。
