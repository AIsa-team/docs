社交情报 agent 采集公开的社交或媒体信号，用于研究、监测、创作者发现或内容分析。它应当把来源记录视为证据、把模型输出视为解读，并把发布或互动视为需要单独授权的写操作。

这套工作流面向来源受限的分析，而不是无限制的监控或自动发帖。

当监测或分析方法可复用时，使用 Agent Skill。当应用必须控制查询、分页、去重、打分、存储或特定来源的处理逻辑时，使用直接 API。

## 推荐工作流

### 1. 明确研究问题

指定主题、实体、时间窗口、平台、语言和所需输出。不要在没有明确目的的情况下大范围采集社交数据。

例如：

- 跟踪某次产品发布在选定公开来源中的讨论情况。
- 找出某个特定社区中反复出现的问题。
- 比较各创作者在指定时间窗口内对某话题的覆盖。
- 为内容简报寻找素材。

### 2. 采集来源受限的记录

使用相关性最高的最小 API 集合，并保留：

- 来源平台和规范 URL。
- 任务需要时保留作者或频道标识。
- 发布时间和获取时间。
- 查询和筛选参数。
- 来源返回的原始指标。

不要把"没有搜到结果"当成"不存在相关讨论"的证明。

### 3. 归一化但不抹掉出处

应用可以为分析而归一化时间戳、标识符、互动字段和文本。请保留原始来源引用，让每条归一化记录仍可审计。

区分：

- 来源提供的字段。
- 应用计算得到的指标。
- 模型生成的标签或摘要。
- 缺失、无法访问或不确定的数据。

### 4. 谨慎分析规律

模型可以聚类主题、比较叙事、总结反复出现的问题或识别候选信号。但它不应编造来源无法佐证的受众画像、意图、情绪、身份或因果关系。

对于重要结论，应比对多条记录，并尽可能使用不止一种来源类型。

### 5. 输出带证据链接的简报

一份有用的结果应包含：

- 范围和时间窗口。
- 来源和采集方法。
- 观察到的主题或变化。
- 有代表性的链接或记录。
- 单独标注的模型解读。
- 数据缺口、抽样限制和不确定性。

### 6. 为外部操作设置关卡

读取公开社交数据，并不等于获得发帖、点赞、关注、回复、私信或修改账号的授权。

执行外部操作之前：

1. 确认已连接的账号和所需权限。
2. 展示确切的内容、对象和预期效果。
3. 在策略要求时获得确认。
4. 以最小范围执行一次操作。
5. 校验产生的外部状态。

## 隐私与安全边界

- 只采集既定目的所需的数据。
- 遵守平台条款、适用的隐私要求和受众预期。
- 不要从社交行为推断敏感特征。
- 不要暴露凭证、私密账号数据或无关的个人信息。
- 把自动互动视为写操作，它带有声誉和合规风险。

## 什么时候未必需要 AIsa

如果应用只使用一个来源、已经具备稳定的认证和合规控制，也不需要模型、可复用 Skills 或其他 AIsa 资源，那么直接对接平台可能更简单。
