<Note>Tasks are live on the dev API (`https://dev-api.aisa.one`) and not yet in production.</Note>

A task is one job, such as *get a post* or *search profiles*, with one input contract and one output schema for every platform it covers. AIsa routes the call to a data source, falls back to another one when the first fails or finds nothing, and maps every answer to the same fields, so the result reads the same whichever source answered.

## Calling a task

Send `POST /v1/tasks/{task_id}` with your AIsa API key. The body has the task input and optional options:

```bash
curl -sS https://dev-api.aisa.one/v1/tasks/social.get_post \
  -H "Authorization: Bearer $AISA_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"input": {"platform": "tiktok", "url": "https://www.tiktok.com/@nasa/video/7300000000000000000"}, "options": {"strategy": "auto"}}'
```

### Options

| | |
| --- | --- |
| `strategy` | `auto` (default for most tasks): try sources in order and stop at the first answer. `waterfall`: continue to the next source after a miss. `merge`: ask sources in parallel and merge their fields. `compare`: return each source's result side by side under `result.by_source`. `any_hit`: report found when any source finds it. |
| `max_providers` | Lower the number of sources a strategy may try. |
| `providers` | `{"only": [...]}` or `{"exclude": [...]}` to restrict sources. |
| `detail` | `full` attaches each source's raw response in `meta.raw`. |

## Response

Every task answers HTTP 200 with the same envelope:

```json
{
  "task": "social.get_post",
  "version": 1,
  "status": "found",
  "result": {
    "platform": "tiktok",
    "post_id": "7300000000000000000",
    "views": 1200
  },
  "meta": {
    "sources": [],
    "attempts": [],
    "missing_fields": {},
    "approximate_fields": [],
    "delivered": true
  }
}
```

| | |
| --- | --- |
| `status` | `found`, `partial` (found, some fields missing) or `not_found`. |
| `result` | The task's result, as documented on its page. A list task returns `{"items": [...]}`. |
| `meta.missing_fields` | Fields of the result that are null, and why. |
| `meta.approximate_fields` | Counts the platform only shows rounded (for example 1.2K). |
| `meta.sources / meta.attempts` | Which source answered and what each attempt returned. |
| `meta.delivered` | Whether the call delivered a result, and so whether it was charged. |

## Billing

A call is charged only when it delivers: `not_found` is free. A `fixed` task charges one price per found call, whatever the strategy. A `per_unit` task charges per returned item, up to `limit`. The live price of a task is in `pricing` of `GET /v1/tasks/{task_id}`; `X-AISA-Max-Price-USD` caps it and `X-AISA-Cost-Mode: quote` returns the price without running the task.

## Retries

Send an `Idempotency-Key` to retry safely: a key is charged at most once. A charged key returns the first result for 24 hours (`Idempotent-Replayed: true`); a key whose earlier call was not charged runs again.

## Errors

| HTTP | |
| --- | --- |
| 400 | `invalid_request`, or `unsupported_route` with the platforms the task supports |
| 404 | `task_not_found`, with the closest task ids |
| 422 | `invalid_input`, or `provider_rejected_input` when the platform rejects the input |
| 502 | `all_providers_failed`: every source failed; not charged |

## Discovering tasks

`GET /v1/tasks` lists the tasks (`?q=` searches, `?domain=` filters). `GET /v1/tasks/{task_id}` returns the input contract, the platforms and the fields each returns, the output schema, billing and price. Add `?lang=zh` for Chinese descriptions.
