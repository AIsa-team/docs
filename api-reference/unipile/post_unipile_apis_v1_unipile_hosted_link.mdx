Returns a HostedAuthUrl that you send the end user to. They complete the LinkedIn sign-in on Unipile's hosted page, so no credentials ever touch your system. **Managed mode (recommended): omit `notify_url`** and AISA handles everything — poll `GET /apis/v1/unipile/me/accounts` until the account appears (usually within seconds of the user finishing the wizard); no webhook infrastructure needed on your side. **Self-hosted mode: pass your own `notify_url`** and Unipile POSTs `{"status":"CREATION_SUCCESS","account_id":"…","name":"…"}` to it when the flow completes — store that account_id, it is the identifier every other endpoint requires, and with your own webhook there is no listing endpoint to re-discover it (managed-mode users read `me/accounts` instead). The `name` you set here is echoed back in self-hosted mode, so use it to map the account to your own user. Reply 200 within 30 seconds or the event is retried five times; consider verifying a shared-secret header on your endpoint. Links expire on Unipile's daily restart regardless of `expiresOn`, so generate a fresh link each time a user wants to connect. Note: re-authorizing the same LinkedIn account creates a new account_id; earlier bindings remain listed until disconnected.

<CodeGroup>
```bash REST
curl -X POST "https://api.aisa.one/apis/v1/unipile/hosted/link" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"type": "create", "providers": ["LINKEDIN"], "api_url": "https://api68.unipile.com:19823", "expiresOn": "2026-12-31T23:59:59.999Z", "name": "your-internal-user-id", "notify_url": "https://example.com/hooks/unipile", "success_redirect_url": "https://example.com/connected", "failure_redirect_url": "https://example.com/failed"}'
```
