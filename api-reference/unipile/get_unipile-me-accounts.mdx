---
title: "My Connected Accounts"
description: "List the LinkedIn accounts connected through your API key."
---

Read side of the managed hosted-auth flow: when you create hosted links without your own `notify_url`, this is where the resulting `account_id` surfaces. Poll after the user finishes the LinkedIn wizard — the account usually appears within seconds. Returns only the accounts connected by this API key's owner; there is deliberately no tenant-wide listing. `status` is one of `running` (operational), `disconnected` (re-authentication needed — send the user a new hosted link with `type=reconnect`), `errored` (service interruption, retried automatically), `paused` (subscription issue), `degraded`/`partial` (per-product states). A freshly connected account is immediately usable even before its first status sync.

This helper endpoint is free of charge.

`GET /apis/v1/unipile/me/accounts` requires your API key in the `Authorization: Bearer` header. The response is `{"accounts": [...]}`, empty until an account is connected.

## Example

<CodeGroup>
```bash REST
curl "https://api.aisa.one/apis/v1/unipile/me/accounts" \
  -H "Authorization: Bearer YOUR_API_KEY"
```
</CodeGroup>
