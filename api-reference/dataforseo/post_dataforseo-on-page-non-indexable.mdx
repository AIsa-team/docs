The crawled pages search engines will not index, each with a `reason` and `url`. Measured at 588 bytes. Reads a finished crawl, so it needs the `id` from `post_dataforseo_on_page_submit` and returns `crawl_progress` plus a `crawl_status` of `max_crawl_pages`, `pages_in_queue` and `pages_crawled` - check those before trusting a small result, because a crawl still running simply has less to report. The reason field is the whole value here - noindex, canonical elsewhere, robots-blocked are very different problems with the same symptom. ## Example

<CodeGroup>
```bash REST
curl -X POST "https://dev-api.aisa.one/apis/v1/dataforseo/on_page/non_indexable" \

  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '[{"id": "...", "limit": "...", "offset": "..."}]'
```
