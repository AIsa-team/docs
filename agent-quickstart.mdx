Use this page as the first document an AI agent reads when a user wants to connect, configure, or use AIsa inside an agent environment such as OpenClaw, Hermes Agent, Claude Code, Cursor, Codex, or another tool-calling assistant.

This page is intentionally short. It points agents to the few docs they need for the current task instead of loading the full [`llms.txt`](https://aisa.one/docs/llms.txt) index into context.

## What AIsa is

AIsa is a unified API gateway for autonomous AI agents. It provides:

- OpenAI-compatible access to LLMs and media models through one model endpoint.
- Agent-facing data APIs for search, social, financial, market, email, and web workflows.
- Pre-built Agent Skills that describe how agents should use AIsa capabilities.
- Usage metering, dashboard logs, and billing through one AIsa account.

## Base endpoints

Use the endpoint that matches the task:

| Use case | Endpoint |
| --- | --- |
| OpenAI-compatible chat, model routing, SDKs | `https://api.aisa.one/v1` |
| AIsa data APIs and non-chat capability APIs | `https://api.aisa.one/apis/v1` |

For most model clients, configure AIsa as an OpenAI-compatible provider using:

```txt
base_url: https://api.aisa.one/v1
api_key:  $AISA_API_KEY
```

## Authentication

Set the API key as an environment variable whenever possible:

```bash
export AISA_API_KEY="<your_aisa_api_key>"
```

Safety rules:

- Never print, log, commit, or expose the API key.
- Prefer environment variables or the agent runtime's secret store over hardcoded config.
- If the user has not provided a key, explain where to create one instead of inventing a placeholder value.

Agent behavior:

1. Configure the model client with `https://api.aisa.one/v1`.
2. Send the API key as a Bearer token in the `Authorization` header.
3. Choose a text, reasoning, or coding model for the agent's main model.
4. Do not choose image, video, embedding, Whisper, or TTS models as the main conversational model.
5. Make a small test call before claiming the setup works.

## Agent setup prompt

Copy this prompt into an agent environment:

```txt
Read https://aisa.one/docs/agent-quickstart.md and help me safely connect, configure, and use AIsa's APIs, Skills, and LLMs in this agent environment.
```

## Do not over-load context

Agents should avoid loading too much documentation by default:

- Do not read `llms-full.txt` unless full documentation ingestion is explicitly requested.
- Do not open every link from `llms.txt`.
- Do not fetch unrelated API pages.
- Do not paste large docs into the conversation when a short summary and links are enough.
- When uncertain, ask which AIsa capability the user wants before reading more docs.

## Minimal verification checklist

Before saying AIsa is configured, verify the relevant part actually works:

- For model setup: perform a small chat completion or model-list check.
- For API setup: make a small request to the selected AIsa API.
- For Skills: confirm the agent loaded the specific Skill docs needed for the task.
- For secrets: confirm the key is stored safely without revealing its value.
