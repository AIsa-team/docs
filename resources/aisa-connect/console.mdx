The [AIsa Console](https://console.aisa.one) lets you try AIsa Connect without code: browse the catalog, connect your own accounts for testing or for your own agents, and manage every connection of your account.

## The Apps directory

Open **Apps** at [console.aisa.one/apps](https://console.aisa.one/apps). It lists two kinds of apps together:

| Type | Meaning |
| --- | --- |
| **Built-in** | AIsa's own APIs and models. No account or provider key; calls bill your AIsa balance |
| **Connect** | Apps that act on an end user's own account. They need the end user's authorization before use |

- The **All** tab shows the whole directory; the **Connected** tab ([console.aisa.one/apps/connected](https://console.aisa.one/apps/connected)) shows the apps that have at least one connected account.
- Search by name, filter by **Type** (Built-in or Connect) and category, and sort by **Featured** or A–Z.
- Missing an app? Use **Request an app**.

The Console calls AIsa Connect with the first enabled API key you created. Without one, it shows **Create an API key to see Connect apps**; create a key in [API Keys](https://console.aisa.one/api-keys) first.

## Connect an account

<Steps>
  <Step title="Open the app">
    Pick a Connect app in the directory to open its page.
  </Step>
  <Step title="Choose Connect account">
    Pick the connection method if the app offers more than one:

    - **Authorize with the app** (`oauth2`): sign in to the app in a new window to give AIsa access. The Console page updates by itself when you finish.
    - **App API key** (`api_key`): paste the key from the app.
    - **App credentials** (`custom_credential`): enter **Credentials (JSON object)** with the field names from the app's documentation, such as `{"storeUrl": "https://shop.example.com", "consumerKey": "ck_...", "consumerSecret": "cs_..."}` for WooCommerce. Values must be strings. The page links to **App documentation**.
  </Step>
  <Step title="Use it">
    The account appears under **Connected accounts** with status **Connected**.
  </Step>
</Steps>

The Console connects accounts as the end user `console-user-<your user id>`, so you do not have to choose an ID. To let an agent or script use the account, pass that ID as `externalUserId`; use **Copy end user ID** on the account. See [Use with agents](/resources/aisa-connect/agents#which-end-user-id-to-use).

Console connections are ordinary connections: they count toward your [connection limit](/resources/aisa-connect/pricing-and-limits#connection-limit), and the API lists them like any other.

## Manage connected accounts

An app's page lists **Connected accounts** for that app across **all** of your end users, including the ones your backend connected through the API.

| Control | What it does |
| --- | --- |
| Status | **Connected** (`active`) or **Needs reconnect** (`needs_reconnect`) |
| **Reconnect** | Reauthorizes the connection in place, for `oauth2` apps. Same as [reconnecting with `connectionId`](/resources/aisa-connect/authorize-users#reconnect-a-connection) |
| **Permissions** | **Share with team** lets every member of the organization use the account. **Tools** turns whole operation types (Read, Write, Delete) or single actions on and off; AIsa refuses the others for every agent. See [Team members](/resources/aisa-connect/concepts#team-members) and [Tools](/resources/aisa-connect/concepts#tools) |
| **Disconnect** | Deletes the connection after you confirm. Actions using it stop working |
| **Copy end user ID** | Copies the connection's `externalUserId` |

In an organization, each account is marked **Only you** or **Shared with team**. You see your own accounts and the ones teammates shared; Reconnect, Permissions and Disconnect appear only on the accounts you connected. The Console uses one of your own API keys, never a teammate's.

## When Connect is unavailable

If the Console shows **App connections aren't available yet**, AIsa Connect is not available in that environment. Contact [developer@aisa.one](mailto:developer@aisa.one).
