The [AIsa Console](https://dev-console.aisa.one/) is where you see what your agents spent and why, find capabilities, manage keys and teammates, and keep your balance from running out.

| Page | Use it to |
| --- | --- |
| [Home](https://dev-console.aisa.one/) | See this month's requests and spend, today's spend, recent failures, and recent requests |
| [Capabilities](https://dev-console.aisa.one/capabilities) | Browse every API and model, read an agent-ready contract, and try a call |
| [Connections](https://dev-console.aisa.one/api-keys) | See agents signed in to AIsa, and create API keys with monthly caps |
| [Usage](https://dev-console.aisa.one/logs) | Inspect each request, filter by result, and group spend by capability, provider, or source |
| [Organization](https://dev-console.aisa.one/settings/members) | Invite teammates, assign roles, group people into projects |
| [Billing](https://dev-console.aisa.one/billing) | Top up, set spend rules and auto-recharge, choose a plan, download invoices |
| [Share & Earn](https://dev-console.aisa.one/referral) | Invite friends and track referral rewards |

Everything in the Console is scoped to the account in the top-left switcher: your personal account or an organization you belong to. Search everything with **⌘K** (Ctrl+K), and press **?** for keyboard shortcuts.

## Home

Home answers "what did I pay for?". The top line is this month's request count and what it cost; empty results and failed calls are listed as free, because AIsa charges only for calls that return a result.

The strip below shows your balance, today's spend (with a progress bar against your daily alert, if you set one), and your spend rule. **Failed in the last 24 hours** groups failures by cause - for example *A required input is missing* - with how often it happened and when; **Diagnose** opens the request with the likely cause and the fix. **Recent requests** lists the latest calls with their source (which agent or key), result, and cost. Click any row for the request detail.

## Capabilities

Capabilities is the catalog of every API and model you can call. Describe what you need in the search box (for example *traffic for a competitor's site*) or filter by category; each card shows the provider, a short description, the starting price, and how many APIs it has.

- **Agent view** walks from category to provider to API to contract, with a breadcrumb. **Copy agent context** copies the current level so you can paste it into your agent.
- An **API contract** is a short, agent-readable description of one endpoint: what it does, when to use it, its price, and its inputs, plus the rule to quote before calling and to ask before paying unless your spend rules allow the call.
- A **provider page** lets you fill in the request fields and watch the cURL, JavaScript, Python, and CLI code update. Running it sends a real, billed call with your key; you are charged only if it returns a result.
- **Models** lists the chat, image, audio, and embedding models with per-token prices, and each model page lets you send a real request.

## Connections

**Agents** are clients signed in to AIsa through the browser (for example Claude Code, Codex, or Cursor). Each one has its own sign-in and can be disconnected on its own; disconnecting signs it out immediately, and its past calls stay in Usage.

**API keys** are for scripts and CI that cannot sign in through a browser. The list shows each key's prefix, monthly cap, what it used this month, and when it was last used. Every call is checked against the key's cap first; at the cap, calls with that key pause until you raise it. The full key is shown only once, when you create it. See [Authentication](/guides/authentication#key-settings) for key settings.

## Usage

Usage is the request-level record of your account. Pick **7 days**, **30 days**, or **This month**; the cards at the top show spend, requests, failed calls, and calls with no result (the last two are free).

- Filter by **All**, **Billed**, **No result**, or **Failed**, and search by endpoint, agent, or `request_id`.
- **Columns** adds capability, endpoint, returned amount, duration, or `request_id`; time and cost are always shown.
- **Group by** totals calls, results, failures, and spend by capability, endpoint, provider, source, or LLM versus non-LLM requests, ordered by spend.
- In an organization, owners, admins, and billing members can narrow usage to one member, project, or key, and export it as CSV.

Click any request for its detail: what came back, why an empty or failed call was free, the likely fix for a failure, and the IDs and timings to copy for support.

## Organization

An organization shares one balance, one set of keys, and one invoice. Every member has one of four roles:

| Role | Can |
| --- | --- |
| **Owner** | Everything; only owners can delete the organization or make someone else an owner |
| **Admin** | Manage members, projects, and every key, and see all usage; cannot pay or change owners |
| **Member** | Create keys, sign agents in, and see their own usage and the organization balance |
| **Billing** | Top up, manage payment methods and invoices, and see all usage; cannot touch keys or people |

- **Members** - invite up to 20 people at once; invitations last 7 days and must be accepted with the invited email. **Manage access** changes a role or projects; **Remove** signs the person's agents out within 60 seconds and, by default, keeps the keys they created working for the organization.
- **Invitations** - resend (which restarts the 7 days) or cancel pending invites.
- **Projects** - group people by team or product line. Projects never change roles, keys, or agent sign-ins.
- **General** - name, URL slug, and logo; owner transfer and organization deletion (both confirmed with an email code); and **Close my account**, which asks you to choose a successor owner for each shared organization you own.

## Billing

- **Balance and top-up** - your available balance, split into balance and bonus credit. Top-ups never expire. Pay by card, or choose another available method such as Alipay, WeChat Pay, or Pix; promo codes are entered here too.
- **Spend rules** - either *ask me before every paid call*, or *run calls under a set amount on their own and ask for anything bigger*. Agents connected through AIsa check this rule on every quote before they spend. You can also ask for an email when a day's spend passes an amount; the alert never pauses calls.
- **Auto Recharge** - when the balance falls below a threshold, top up a set amount from your saved card, within the daily and monthly caps you choose (at most three automatic top-ups in 24 hours).
- **Plans** - pay as you go, or a monthly Go-to-Market plan whose credit is used before your balance. Cancel or re-enable renewal from the current plan.
- **History and invoices** - completed top-ups and plan payments; organizations can also keep billing details and download invoices.

In an organization, only owners and billing members can pay; admins can also change the spend rules.

## Share & Earn

Share & Earn has your invite link and the current reward terms, a calculator for what you could earn, and the list of people who joined with your link. **Make my badge** creates a shareable card with your usage highlights and invite code; spend is never shown on it.

## Query usage with an API key

`GET https://dev-api.aisa.one/v1/usage` returns aggregate usage for the authenticated key by default. Use the same key that made the calls. It is not a per-request log; use [Usage](#usage) to inspect individual calls.

```bash
# Positive Unix seconds in UTC; this example selects the last 24 hours.
start_time=$(python3 -c 'import time; print(int(time.time()) - 86400)')
curl --fail-with-body --silent --show-error --get \
  "https://dev-api.aisa.one/v1/usage" \
  --header "Authorization: Bearer ${AISA_API_KEY:?Set AISA_API_KEY}" \
  --data-urlencode "start_time=$start_time" \
  --data-urlencode "bucket_width=1d" \
  --data-urlencode "scope=key"
```

| Parameter | Meaning |
| --- | --- |
| `start_time` | Required positive Unix timestamp in **seconds**, not milliseconds or a date string. |
| `end_time` | Optional Unix seconds; defaults to the current time. Must be later than start_time. The interval includes start and excludes end: `[start_time, end_time)`. |
| Window | At most **31 days** (31 × 24 hours); split longer periods into adjacent windows. |
| `bucket_width` | Only `1d` is supported, with UTC daily buckets. |
| `scope` | Defaults to `key`. `account` requires OAuth authentication; an ordinary API key cannot request account scope. |

`totals.charged_micros_usd` is the actual charged amount; divide integer micro-USD by 1,000,000 for USD. `totals.usage_value_micros_usd` is usage value and can differ from the charge. Compare the same key, time window and currency when reconciling. This aggregate does not prove the outcome of a specific request or that a historical top-up succeeded.

## When data fails to load

If a section cannot load its data, it shows the error in place with a **Retry** button; the rest of the page keeps working.
