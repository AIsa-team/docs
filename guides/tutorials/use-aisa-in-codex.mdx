Configure AIsa in OpenAI's Codex CLI using a single provider block in `~/.codex/config.toml` and your API key.

AIsa endpoint:

```txt
https://api.aisa.one/v1
```

## Prerequisites

Before you start, make sure you have:

- An AIsa API key ([console.aisa.one/api-keys](https://console.aisa.one/api-keys))
- A terminal on macOS, Linux, or Windows WSL2

## 1. Install Codex

```bash
npm install -g @openai/codex
```

Or with Homebrew:

```bash
brew install codex
```

Verify the installation:

```bash
codex --version
```

## 2. Add AIsa as the model provider

Export your AIsa API key (add it to `~/.zshrc` or `~/.bashrc` to persist it):

```bash
export AISA_API_KEY="sk-aisa-..."
```

Then add this to `~/.codex/config.toml` (create the file if it doesn't exist):

```toml
model = "gpt-5.3-codex"
model_provider = "aisa"

[model_providers.aisa]
name = "AIsa"
base_url = "https://api.aisa.one/v1"
env_key = "AISA_API_KEY"
wire_api = "responses"
```

- `env_key` tells Codex which environment variable holds your key.
- `wire_api = "responses"` sends requests to AIsa's `POST /v1/responses` endpoint. Codex only supports the Responses API; `wire_api = "chat"` is rejected at startup.
- Swap `model` for another model that works on `/v1/responses`, such as `gpt-5.5`, `gpt-5.4`, or `deepseek-v4.1-flash`. Not every model in the [catalog](/guides/models) serves this route.

## 3. Start Codex and connect AIsa capabilities

```bash
codex
```

The provider block covers chat. To give Codex access to AIsa's data and tool catalog, add the AIsa MCP server:

```bash
codex mcp add aisa --url https://mcp.aisa.one/mcp
```

Codex automatically opens your browser for OAuth authentication; approve access and no key is copied.

<Accordion title="Use your API key instead of OAuth">
  For headless environments, reuse the `AISA_API_KEY` exported for the provider. Codex reads it at runtime, so the key never lands in `config.toml`:

  ```bash
  codex mcp add aisa --url https://mcp.aisa.one/mcp --bearer-token-env-var AISA_API_KEY
  ```
</Accordion>

Codex now has the AIsa tools: `search`, `list_categories`, `get_details`, and `batch_quote` (prices exact calls without running them) are free; `batch_use` runs the calls and is billed per call.

Try:

```txt
Use AIsa capabilities to search the web and summarize the latest information about Codex CLI.
```

## Quick reference

| Item | Value |
| --- | --- |
| Config file | `~/.codex/config.toml` |
| `base_url` | `https://api.aisa.one/v1` |
| `env_key` | `AISA_API_KEY` |
| `wire_api` | `responses` |
| Default model | `gpt-5.3-codex` |
| AIsa MCP server | `codex mcp add aisa --url https://mcp.aisa.one/mcp` (OAuth) |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| Authentication error (401) | Confirm `AISA_API_KEY` is exported: `echo $AISA_API_KEY` |
| "unexpected status 404" | Make sure `base_url` is exactly `https://api.aisa.one/v1` |
| `wire_api = "chat" is no longer supported` | Set `wire_api = "responses"` |
| `model_route_not_supported` or 400 from `/v1/responses` | The model does not serve the Responses API; switch to `gpt-5.5`, `gpt-5.4`, or `deepseek-v4.1-flash` |
| Model not found | Use an exact model ID from the [catalog](/guides/models) |
| Codex still asks for ChatGPT login | Confirm `model_provider = "aisa"` is set at the top level of `config.toml` |
| AIsa tools missing | Run `codex mcp list`; if **aisa** is not authorized, run `codex mcp login aisa` and restart Codex |
