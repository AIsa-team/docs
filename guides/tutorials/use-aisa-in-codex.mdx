Codex has a built-in MCP client. Add AIsa as a remote MCP server, sign in once, and Codex can discover and call AIsa capabilities across web research, finance, social, SEO, sales, and more.

AIsa MCP server:

```txt
https://mcp.aisa.one/mcp
```

## Prerequisites

Before you start, make sure you have:

- An AIsa account ([console.aisa.one](https://console.aisa.one)). You sign in through the browser.
- A terminal on macOS, Linux, or Windows WSL2

## 1. Install Codex

```bash
npm install -g @openai/codex
```

Or with Homebrew:

```bash
brew install codex
```

Verify the installation:

```bash
codex --version
```

## 2. Add the AIsa MCP server

```bash
codex mcp add aisa --url https://mcp.aisa.one/mcp
```

Codex detects that AIsa uses OAuth and opens your browser. Sign in to AIsa and approve access; no key is copied. On a machine without a browser, run `codex mcp login aisa --no-browser` and open the printed URL elsewhere.

<Accordion title="Use your API key instead of OAuth">
  For headless environments, export your AIsa key and tell Codex which variable holds it. Codex reads it at runtime, so the key never lands in `config.toml`:

  ```bash
  export AISA_API_KEY="sk-aisa-..."
  codex mcp add aisa --url https://mcp.aisa.one/mcp --bearer-token-env-var AISA_API_KEY
  ```
</Accordion>

## 3. Verify

```bash
codex mcp list
```

**aisa** should be listed as `enabled`, with `OAuth` (or `Bearer token`) in the Auth column. Start a new Codex session to load the tools; inside Codex, `/mcp` shows the connected servers.

## 4. Use AIsa capabilities

```bash
codex
```

Codex now has the AIsa tools. `search`, `list_categories`, `get_details`, `batch_get_schema`, and `batch_quote` (prices exact calls without running them) are free; `use` and `batch_use` run calls and are billed per call.

Try:

```txt
Use AIsa capabilities to search the web and summarize the latest information about Codex CLI.
```

## Optional: run Codex on AIsa models

Codex can also use AIsa as its model provider. This needs an AIsa API key ([console.aisa.one/api-keys](https://console.aisa.one/api-keys)) exported as `AISA_API_KEY`. Add this to `~/.codex/config.toml`:

```toml
model = "gpt-5.5"
model_provider = "aisa"

[model_providers.aisa]
name = "AIsa"
base_url = "https://api.aisa.one/v1"
env_key = "AISA_API_KEY"
wire_api = "responses"
```

- `env_key` tells Codex which environment variable holds your key.
- Codex only supports `wire_api = "responses"`, so pick a model that lists `POST /v1/responses` in the [catalog](/guides/models), such as `gpt-5.5`, `gpt-5.4`, or `gpt-5.3-codex`.

## Quick reference

| Item | Value |
| --- | --- |
| Add AIsa | `codex mcp add aisa --url https://mcp.aisa.one/mcp` (OAuth starts automatically) |
| Sign in again | `codex mcp login aisa` |
| Check status | `codex mcp list`, or `/mcp` inside Codex |
| API key | Not needed for MCP; optional `--bearer-token-env-var AISA_API_KEY` |
| Optional model provider | `base_url = "https://api.aisa.one/v1"`, `wire_api = "responses"` |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| AIsa tools missing | Run `codex mcp list`. If **aisa** shows `Not logged in`, run `codex mcp login aisa`, then start a new session |
| Browser didn't open | Run `codex mcp login aisa --no-browser` and open the printed URL |
| `wire_api = "chat"` is no longer supported | Set `wire_api = "responses"` in the provider block |
| Model provider returns 401 | Confirm `AISA_API_KEY` is exported in the shell that runs Codex |
| Model provider returns 404 | Make sure `base_url` is exactly `https://api.aisa.one/v1` |
| Model not found | Use an exact model ID that supports `POST /v1/responses` in the [catalog](/guides/models) |
