Hermes Agent has a built-in MCP client. Add AIsa as a remote MCP server, sign in once, and Hermes can discover and call AIsa capabilities across web research, finance, social, SEO, sales, and more.

AIsa MCP server:

```txt
https://mcp.aisa.one/mcp
```

## Prerequisites

Before you start, make sure you have:

- An AIsa account ([console.aisa.one](https://console.aisa.one)). You sign in through the browser.
- A terminal on macOS, Linux, or Windows WSL2

## 1. Install Hermes Agent

Run the official installer:

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

Reload your shell:

```bash
source ~/.zshrc
```

Verify the installation:

```bash
hermes doctor
```

## 2. Add the AIsa MCP server

Run this in a terminal, not inside a Hermes session:

```bash
hermes mcp add aisa --url https://mcp.aisa.one/mcp --auth oauth
```

Hermes opens your browser. Sign in to AIsa and approve access; no key is copied. To sign in again later, run `hermes mcp login aisa`.

<Accordion title="Use your API key instead of OAuth">
  For headless machines, add the server with header auth:

  ```bash
  hermes mcp add aisa --url https://mcp.aisa.one/mcp --auth header
  ```

  Answer `Y` when Hermes asks whether the server requires authentication, then paste your AIsa key at **API key / Bearer token**. Hermes stores it in its `.env` file as `MCP_AISA_API_KEY` and references it from `config.yaml`.
</Accordion>

## 3. Verify

```bash
hermes mcp test aisa
```

Hermes should report `Connected` and `Tools discovered: 7`. Start a new Hermes session to load the tools, or run `/reload-mcp` in a running session.

## 4. Use AIsa capabilities

```bash
hermes
```

Hermes now has the AIsa tools. `search`, `list_categories`, `get_details`, `batch_get_schema`, and `batch_quote` (prices exact calls without running them) are free; `use` and `batch_use` run calls and are billed per call.

Try:

```txt
Use AIsa capabilities to search the web and summarize the latest information about Hermes Agent.
```

## Optional: use AIsa as the model provider

Hermes can also run on models from the AIsa catalog. This needs an AIsa API key ([console.aisa.one/api-keys](https://console.aisa.one/api-keys)).

Run:

```bash
hermes model
```

Select:

```txt
Custom Model / OpenAI-compatible endpoint
```

![Select Custom Model / OpenAI-compatible endpoint](https://assets.aisaskills.com/custom-endpoint.png)

When Hermes asks for the API endpoint and API key, enter:

```txt
API base URL: https://api.aisa.one/v1
API key: YOUR_AISA_API_KEY
```

If the endpoint is valid, Hermes confirms access to the AIsa model list:

```txt
Verified endpoint via https://api.aisa.one/v1/models
167 model(s) visible
```

![Hermes API compatibility mode prompt](https://assets.aisaskills.com/api-model.png)

Pick mode `1. Auto-detect` or `2. Chat Completions`; both work, since the base URL ends in `/v1`. Mode 2 is recommended because it is explicit and easier to debug.

| Mode | Required base URL | Use for |
| --- | --- | --- |
| 1. Auto-detect | `https://api.aisa.one/v1` | Resolves to Chat Completions for `/v1` URLs |
| 2. Chat Completions | `https://api.aisa.one/v1` | Standard OpenAI-compatible endpoints |
| 3. Responses / Codex | `https://api.aisa.one/v1` | Codex CLI and reasoning models needing server-side state |
| 4. Anthropic Messages | `https://api.aisa.one/` (no `/v1`) | Claude Code and other Anthropic-native clients |

> If you pick mode 4, remove `/v1` from the base URL; Anthropic clients append `/v1/messages` automatically.

Then enter a model number or type a model name, for example `gpt-5.5`. Choose a text, reasoning, or coding model, not an image, video, embedding, Whisper, or TTS model. When Hermes asks for the context length, press Enter to auto-detect.

## Quick reference

| Item | Value |
| --- | --- |
| Add AIsa | `hermes mcp add aisa --url https://mcp.aisa.one/mcp --auth oauth` |
| Sign in again | `hermes mcp login aisa` |
| Check connection | `hermes mcp test aisa` |
| Reload in a session | `/reload-mcp` |
| Optional model provider | `Custom Model / OpenAI-compatible endpoint`, `https://api.aisa.one/v1`, mode `2. Chat Completions` |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `hermes: command not found` | Run `source ~/.zshrc` or reopen your terminal |
| OAuth fails in a script or CI | OAuth needs an interactive terminal. Use `--auth header` with an API key instead |
| AIsa tools missing or 401 | Run `hermes mcp login aisa`, then `hermes mcp test aisa`, then `/reload-mcp` |
| Added the server inside a running session and sign-in timed out | Run `hermes mcp login aisa` in a separate terminal |
| Model endpoint verification fails | Make sure the base URL is `https://api.aisa.one/v1` |
| Selected the wrong model | Re-run `hermes model` and choose a text or coding model |
