This guide has two parts:

1. Configure AIsa as OpenClaw's LLM provider.
2. Add the AIsa MCP server so OpenClaw can use AIsa's data and tools.

## 1. Use AIsa as the LLM provider

If you want full control over OpenClaw's model configuration — custom model lists, fallback chains, auth profiles stored in your system keychain, or per-channel routing — edit `openclaw.json` directly.

### Step 1: Get your AIsa API key

<Steps>
  <Step title="Log in to the dashboard">
    [console.aisa.one](https://console.aisa.one/)
  </Step>
  <Step title="Navigate to API Keys">
    [console.aisa.one/api-keys](https://console.aisa.one/api-keys)
  </Step>
  <Step title="Create a new key">
    Give it a label like `openclaw-local`. Copy the value (starts with `sk-aisa-`) immediately — it is shown only once.
  </Step>
</Steps>

### Step 2: Set your API key

Add the key to `~/.openclaw/openclaw.json` or export it in your shell:

```bash
export AISA_API_KEY="sk-aisa-..."
```

<Tip>
  Prefer an environment variable over hardcoding the key in `openclaw.json`. See [Authentication](/guides/authentication) for rotation and storage best practices.
</Tip>

### Step 3: Configure the AIsa provider

Add this block to your `~/.openclaw/openclaw.json`:

```json
{
  "env": {
    "AISA_API_KEY": "sk-aisa-..."
  },
  "models": {
    "mode": "merge",
    "providers": {
      "aisa": {
        "baseUrl": "https://api.aisa.one/v1",
        "apiKey": "${AISA_API_KEY}",
        "api": "openai-completions",
        "models": [
          { "id": "gpt-5.4-mini", "name": "GPT-5.4 Mini" },
          { "id": "kimi-k2.5", "name": "Kimi K2.5" },
          { "id": "claude-opus-4-8", "name": "Claude Opus 4.8" },
          { "id": "gemini-3.5-flash", "name": "Gemini 3.5 Flash" },
          { "id": "deepseek-v4.1-flash", "name": "DeepSeek V4.1 Flash" },
          { "id": "qwen3.7-max", "name": "Qwen3.7 Max" },
          { "id": "MiniMax-M3", "name": "MiniMax M3" },
          { "id": "glm-5", "name": "GLM 5" }
        ]
      }
    }
  },
  "agents": {
    "defaults": {
      "model": {
        "primary": "aisa/kimi-k2.5"
      },
      "models": {
        "aisa/kimi-k2.5": {}
      }
    }
  }
}
```

OpenClaw now recognizes the `aisa` provider. Reference any model using the `aisa/<model-id>` format.

### Step 4: Restart OpenClaw

```bash
openclaw gateway restart
```

Your agents will now route requests through AIsa.

## 2. Connect AIsa resource capabilities

The provider configuration covers chat. To give OpenClaw access to AIsa's data and tool catalog, add the AIsa MCP server and sign in with OAuth:

```bash
openclaw mcp add aisa --url https://mcp.aisa.one/mcp --auth oauth
openclaw mcp login aisa
```

Approve access in the browser; no key needs to be copied.

<Accordion title="Use your API key instead of OAuth">
  For headless hosts, pass the API key as a Bearer header. The shell expands `$AISA_API_KEY` when you run the command, so it must be exported in this shell, even if Step 2 put the key only in the `env` block of `openclaw.json`. The `:?` check stops the command instead of saving an empty token, and the expanded key is saved directly into `openclaw.json`:

  ```bash
  export AISA_API_KEY="sk-aisa-..."
  openclaw mcp add aisa --url https://mcp.aisa.one/mcp --header "Authorization=Bearer ${AISA_API_KEY:?Set AISA_API_KEY first}"
  ```
</Accordion>

Verify the connection with `openclaw mcp probe`. OpenClaw now has access to the AIsa tools: `search`, `list_categories`, `get_details`, and `batch_quote` (prices exact calls without running them) are free; `batch_use` runs the calls and is billed per call.

Try:

```txt
Use AIsa capabilities to search the web and summarize the latest information about OpenClaw.
```

## LLM model format

Always use the `aisa/<model-id>` format — for example, `aisa/kimi-k2.5`, `aisa/gpt-5.4`, or `aisa/claude-opus-4-8`. Add any supported model to the `models` array in your provider config; see the full list in the [model catalog](/guides/models).

## Advanced configuration

### Fallback chains

If the primary model fails (due to an upstream outage or rate limit), OpenClaw can automatically retry with a fallback model:

```json
{
  "agents": {
    "defaults": {
      "model": {
        "primary": "aisa/kimi-k2.5",
        "fallbacks": ["aisa/gpt-5.4-mini"]
      },
      "models": {
        "aisa/kimi-k2.5": {},
        "aisa/gpt-5.4-mini": {}
      }
    }
  }
}
```

### Auth profiles (keychain storage)

Keep your API key out of `openclaw.json` by storing it in your system keychain:

<Steps>
  <Step title="Declare an auth profile">
    ```json
    {
      "auth": {
        "profiles": {
          "aisa:default": {
            "provider": "aisa",
            "mode": "api_key"
          }
        }
      }
    }
    ```
  </Step>
  <Step title="Store the key via OpenClaw CLI">
    ```bash
    openclaw auth set aisa:default --key "$AISA_API_KEY"
    ```
  </Step>
  <Step title="Reference the profile in your provider config">
    ```json
    "providers": {
      "aisa": {
        "apiKey": "auth:aisa:default",
        "baseUrl": "https://api.aisa.one/v1",
        "api": "openai-completions"
      }
    }
    ```
  </Step>
</Steps>

### Per-channel models

Run a different model on each messaging platform:

```json
{
  "telegram": {
    "agents": {
      "defaults": {
        "model": { "primary": "aisa/kimi-k2.5" }
      }
    }
  },
  "discord": {
    "agents": {
      "defaults": {
        "model": { "primary": "aisa/claude-opus-4-8" }
      }
    }
  }
}
```

## Troubleshooting

<AccordionGroup>

<Accordion title="'No API key found for provider aisa'">
**Fix:**
1. Confirm `AISA_API_KEY` is set: `echo $AISA_API_KEY`
2. Verify `openclaw.json` references `${AISA_API_KEY}` (not a literal string).
3. Restart OpenClaw so it re-reads environment variables.
4. As a last resort, hardcode the key to confirm the rest of the config works, then move it back to an environment variable.
</Accordion>

<Accordion title="Authentication errors (401 / 403)">
**Fix:**
1. Confirm the key is valid in the [dashboard](https://console.aisa.one).
2. Ensure `baseUrl` is exactly `https://api.aisa.one/v1` (with no trailing slash).
3. See [Authentication](/guides/authentication) for rotation guidance.
</Accordion>

<Accordion title="Model not working">
**Fix:**
1. Double-check the model ID against the [catalog](/guides/models).
2. Make sure the model is listed in `models.providers.aisa.models`.
3. Reference it as `aisa/<model-id>`.
</Accordion>

<Accordion title="AIsa tools missing">
**Fix:**
1. Run `openclaw mcp list` and confirm **aisa** is configured.
2. Run `openclaw mcp login aisa` to sign in again.
3. Run `openclaw mcp reload` so the next turn picks up the updated connection.
</Accordion>

</AccordionGroup>
