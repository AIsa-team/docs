Cursor has a built-in MCP client. Add AIsa as a remote MCP server, sign in once, and Cursor's agent can discover and call AIsa capabilities across web research, finance, social, SEO, sales, and more.

AIsa MCP server:

```txt
https://mcp.aisa.one/mcp
```

## Prerequisites

Before you start, make sure you have:

- An AIsa account ([console.aisa.one](https://console.aisa.one)). You sign in through the browser.
- [Cursor](https://cursor.com) installed

## 1. Add the AIsa MCP server

Add AIsa to `~/.cursor/mcp.json` for all projects, or to `.cursor/mcp.json` for one project. Create the file if it doesn't exist:

```json
{
  "mcpServers": {
    "aisa": { "url": "https://mcp.aisa.one/mcp" }
  }
}
```

## 2. Sign in

<Steps>
  <Step title="Open Tools & MCPs">
    Press `Cmd+Shift+J` (macOS) or `Ctrl+Shift+J` (Windows/Linux) to open Cursor Settings, then select **Tools & MCPs**.
  </Step>
  <Step title="Authenticate">
    Make sure **aisa** is enabled. It shows **Needs authentication**; click **Authenticate**, sign in to AIsa in the browser, and approve access. No key is copied.
  </Step>
</Steps>

<Accordion title="Use your API key instead of OAuth">
  Pass the key as a Bearer header. Cursor resolves `${env:AISA_API_KEY}` from the environment where it was launched, keeping the key out of the configuration file. Add `export AISA_API_KEY="sk-aisa-..."` to `~/.zshrc` or `~/.bashrc`, then quit Cursor and reopen it from a new terminal with `cursor .` (apps launched from the Dock may not inherit shell variables). An unset variable sends an empty token:

  ```json
  {
    "mcpServers": {
      "aisa": {
        "url": "https://mcp.aisa.one/mcp",
        "headers": { "Authorization": "Bearer ${env:AISA_API_KEY}" }
      }
    }
  }
  ```
</Accordion>

<Accordion title="Cursor CLI (cursor-agent)">
  `cursor-agent` reads the same `mcp.json`. Approve the server, then sign in:

  ```bash
  cursor-agent mcp enable aisa
  cursor-agent mcp login aisa
  ```

  Run `cursor-agent mcp list-tools aisa` to confirm the tools are available.
</Accordion>

## 3. Use AIsa capabilities

Cursor's agent now has the AIsa tools. `search`, `list_categories`, `get_details`, `batch_get_schema`, and `batch_quote` (prices exact calls without running them) are free; `use` and `batch_use` run calls and are billed per call.

Try:

```txt
Use AIsa capabilities to search the web and summarize the latest information about Cursor.
```

## Optional: use AIsa models

Cursor also accepts an OpenAI-compatible API key, so chat and agent requests can run on models from the AIsa catalog. This needs an AIsa API key ([console.aisa.one/api-keys](https://console.aisa.one/api-keys)).

<Steps>
  <Step title="Configure the endpoint">
    In Cursor Settings → **Models** → **API Keys**, paste your AIsa key (`sk-aisa-...`) into **OpenAI API Key** and turn on **Use OpenAI API Key**. Then turn on **Override OpenAI Base URL** and enter `https://api.aisa.one/v1`.
  </Step>
  <Step title="Add models">
    On the same page, click **Add Custom Model** and enter exact AIsa model IDs, for example `gpt-5.5`, `kimi-k2.5`, `claude-opus-4-8`, or `deepseek-v4.1-flash`. Enable them, then pick one in the model picker. The full list is in the [model catalog](/guides/models).
  </Step>
</Steps>

<Note>
  Custom API keys apply to Cursor's chat and agent requests. Cursor-native features such as Tab autocomplete continue to use Cursor's own models and subscription.
</Note>

## Quick reference

| Item | Value |
| --- | --- |
| MCP config | `"aisa": { "url": "https://mcp.aisa.one/mcp" }` in `~/.cursor/mcp.json` or `.cursor/mcp.json` |
| Sign-in | Cursor Settings → **Tools & MCPs** → **aisa** → **Authenticate** |
| API key | Not needed for MCP; optional Bearer header for headless use |
| Optional models | **Override OpenAI Base URL** `https://api.aisa.one/v1`, exact IDs from the [catalog](/guides/models) |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| **aisa** not listed in **Tools & MCPs** | Check that `mcp.json` is valid JSON and in the right location, then reload Cursor |
| Still shows **Needs authentication** | Click **Authenticate** again and finish the sign-in in the browser |
| AIsa tools missing in chat | In **Tools & MCPs**, turn **aisa** off and on to reload it |
| `cursor-agent` says the server has not been approved | Run `cursor-agent mcp enable aisa`, then `cursor-agent mcp login aisa` |
| Model requests fail with 401 or 404 | Confirm the base URL is exactly `https://api.aisa.one/v1` and the key is valid in the [console](https://console.aisa.one) |
| "Invalid model" errors | The model name must match a catalog ID exactly, with no `aisa/` prefix |
