Cursor lets you bring your own OpenAI-compatible API key. Point it at AIsa's endpoint, and every model in the AIsa catalog becomes available in Cursor's chat and agent modes.

AIsa endpoint:

```txt
https://api.aisa.one/v1
```

## Prerequisites

Before you start, make sure you have:

- An AIsa API key ([console.aisa.one/api-keys](https://console.aisa.one/api-keys))
- [Cursor](https://cursor.com) installed

## 1. Open Cursor's model settings

<Steps>
  <Step title="Open Cursor Settings">
    Press `Cmd+Shift+J` (macOS) or `Ctrl+Shift+J` (Windows/Linux), or click the gear icon in the top-right corner.
  </Step>
  <Step title="Go to Models">
    Select the **Models** tab, then scroll to the **API Keys** section.
  </Step>
</Steps>

## 2. Configure the AIsa endpoint

<Steps>
  <Step title="Enter your AIsa key">
    In the **OpenAI API Key** field, paste your AIsa key (`sk-aisa-...`).
  </Step>
  <Step title="Override the base URL">
    Enable **Override OpenAI Base URL** and enter:

    ```txt
    https://api.aisa.one/v1
    ```
  </Step>
  <Step title="Verify">
    Click **Verify**. Cursor sends a test request through AIsa; a green checkmark confirms the endpoint and key are working.
  </Step>
</Steps>

## 3. Add AIsa models

In the model list on the same **Models** page, click **Add model** and enter the exact AIsa model ID you want to use, for example:

```txt
gpt-5.5
kimi-k2.5
claude-opus-4-8
deepseek-v4.1-flash
```

Enable the models you added, then select one from the model picker in chat or agent mode. The full list of IDs is in the [model catalog](/guides/models).

<Note>
  Custom API keys apply to Cursor's chat and agent requests. Cursor-native features such as Tab autocomplete continue to use Cursor's own models and subscription.
</Note>

## 4. Connect AIsa capabilities

The model settings cover chat. To give Cursor's agent access to AIsa's data and tool catalog, add the AIsa MCP server to `~/.cursor/mcp.json` (or `.cursor/mcp.json` in a project):

```json
{
  "mcpServers": {
    "aisa": { "url": "https://mcp.aisa.one/mcp" }
  }
}
```

Open **Cursor Settings → MCP**, click **Needs login** next to **aisa**, and approve access in the browser. No key is copied.

<Accordion title="Use your API key instead of OAuth">
  Pass the key as a Bearer header. Cursor resolves `${env:AISA_API_KEY}` from the environment where it was launched, keeping the key out of the configuration file. Because the model settings above store the key only inside Cursor, first add `export AISA_API_KEY="sk-aisa-..."` to `~/.zshrc` or `~/.bashrc`, then quit Cursor and reopen it from a new terminal with `cursor .` (apps launched from the Dock may not inherit shell variables). An unset variable sends an empty token:

  ```json
  {
    "mcpServers": {
      "aisa": {
        "url": "https://mcp.aisa.one/mcp",
        "headers": { "Authorization": "Bearer ${env:AISA_API_KEY}" }
      }
    }
  }
  ```
</Accordion>

Cursor's agent now has five AIsa tools: `search`, `list_categories`, and `get_details` are free; `use` and `batch_use` are billed per call.

Try:

```txt
Use AIsa capabilities to search the web and summarize the latest information about Cursor.
```

## Quick reference

| Item | Value |
| --- | --- |
| Settings location | Cursor Settings → Models → API Keys |
| OpenAI API Key field | Your AIsa key (`sk-aisa-...`) |
| Override OpenAI Base URL | `https://api.aisa.one/v1` |
| Model names | Exact IDs from the [catalog](/guides/models), e.g. `kimi-k2.5` |
| AIsa MCP server | `"aisa": { "url": "https://mcp.aisa.one/mcp" }` in `~/.cursor/mcp.json`, then **Needs login** |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| Verify fails | Confirm the base URL is exactly `https://api.aisa.one/v1` and the key is valid in the [dashboard](https://console.aisa.one) |
| Model not selectable | Add it under **Add model** with the exact catalog ID, then toggle it on |
| "Invalid model" errors | The typed model name must match a catalog ID exactly — no `aisa/` prefix in Cursor |
| Tab autocomplete unchanged | Expected — custom keys cover chat/agent only |
| AIsa tools missing | Check **Cursor Settings → MCP**: the JSON must be valid and **aisa** signed in; toggle the server off and on to reload |
