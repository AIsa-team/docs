Pi has a built-in MCP client. Add AIsa as a remote MCP server, sign in once, and Pi can discover and call AIsa capabilities across web research, finance, social, SEO, sales, and more.

AIsa MCP endpoint:

```txt
https://mcp.aisa.one/mcp
```

## Prerequisites

Before you start, make sure you have:

- An AIsa account ([console.aisa.one](https://dev-console.aisa.one)) to sign in through the browser
- [Pi](https://pi.dev) installed with built-in MCP support (verify with `pi mcp --help`)

## 1. Add the AIsa MCP server

```bash
pi mcp add aisa \
  --url https://mcp.aisa.one/mcp \
  --description "AIsa capability layer: discover and call APIs across web, finance, social, SEO, sales, and more."
```

This registers the server globally in `~/.pi/agent/mcp.json`. Pass `-l` to register it in the current project's `.pi/mcp.json` instead.

## 2. Sign in

```bash
pi mcp login aisa
```

Pi opens your browser. Approve access to complete authentication — no key needs to be copied.

<Accordion title="Use your API key instead of OAuth">
  For headless environments, export the key and add the server with a Bearer token read from the environment so the key never lands in a config file:

  ```bash
  export AISA_API_KEY="sk-aisa-..."

  pi mcp add aisa \
    --url https://mcp.aisa.one/mcp \
    --bearer-token-env-var AISA_API_KEY
  ```

  Add the `export` command to `~/.zshrc` or `~/.bashrc` so every new terminal session has it.
</Accordion>

## 3. Verify and reload

Check the connection:

```bash
pi mcp list
```

You should see:

```txt
aisa: connected, 7 tools (codemode, global)
  https://mcp.aisa.one/mcp
  tools: list_categories, search, get_details, batch_get_schema, batch_quote, use, batch_use
```

If you added the server from inside an active Pi session, run `/reload` so the session picks up the new tools.

## 4. Use AIsa capabilities

Ask Pi for anything AIsa can fetch, for example:

```txt
Use AIsa to check the recent posts of Sam Altman. Ask me before any paid call.
```

Pi searches the AIsa catalog, inspects the matching operation's schema, quotes the call, runs it, and reports the cost. The tools work as follows:

| Tool | What it does | Billing |
| --- | --- | --- |
| `list_categories` | Lists capability categories | Free |
| `search` | Finds operations by natural-language task | Free |
| `get_details` | Returns the full contract (schemas, side effects, pitfalls) for up to 20 tools; also served as `batch_get_schema` | Free |
| `batch_quote` | Prices up to 20 exact calls without running them | Free |
| `batch_use` | Runs up to 20 quoted calls | Billed |
| `use` | Deprecated single-call form | Billed |

## Quick reference

| Item | Value |
| --- | --- |
| MCP URL | `https://mcp.aisa.one/mcp` |
| Add command | `pi mcp add aisa --url https://mcp.aisa.one/mcp` |
| Sign in | `pi mcp login aisa` |
| API key alternative | `--bearer-token-env-var AISA_API_KEY` on `pi mcp add` |
| Global config | `~/.pi/agent/mcp.json` |
| Verify | `pi mcp list` |
| Load into a running session | `/reload` |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `pi mcp list` shows an auth error (401) | Run `pi mcp login aisa`. If using an API key, confirm `echo $AISA_API_KEY` prints your key in the shell launching Pi. |
| AIsa tools missing in the current session | Run `/reload`, or start a new Pi session. |
| `pi mcp` is not a command | Update Pi to a version with built-in MCP support. |
| Want AIsa in one project only | Add the server with `-l`; Pi reads `.pi/mcp.json` only after you trust the project. |
