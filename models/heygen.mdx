Use `heygen-video-1` to generate one video from text, a first-frame image, or reference images. Both endpoints use your AIsa API key and the same task ID. Video generation is billed once per task according to its duration and resolution.

## Create a video

Set the native base URL to `https://api.aisa.one/v1/heygen`. Submit a prompt with `mode` set to `text_to_video`. The response is HTTP 202.

```bash
curl -sS https://api.aisa.one/v1/heygen/v3/models/videos \
  -H "x-api-key: $AISA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"heygen-video-1","mode":"text_to_video","prompt":"A blue paper boat on a pond.","duration":5,"resolution":"480p","aspect_ratio":"16:9"}'
```

```json
{"data":{"video_id":"video_task_example","status":"pending","input_video_duration":0}}
```

## Retrieve the result

Set `VIDEO_ID` to the returned `data.video_id`. Poll until `data.status` is `completed`, `failed`, or `cancelled`. Download a completed video from `data.video_url` before the signed link expires. A failed task includes `failure_message`.

```bash
curl -sS "https://api.aisa.one/v1/heygen/v3/models/videos/$VIDEO_ID" \
  -H "x-api-key: $AISA_API_KEY"
```

## AIsa video API

The shared endpoint returns the task ID as `id` and the completed video as `result.video_url`. You can query the same task using either API.

```bash
curl -sS https://api.aisa.one/v1/video/generations \
  -H "Authorization: Bearer $AISA_API_KEY" -H "Content-Type: application/json" \
  -d '{"model":"heygen-video-1","prompt":"A blue paper boat on a pond.","duration":5}'

curl -sS "https://api.aisa.one/v1/video/generations/$VIDEO_ID" \
  -H "Authorization: Bearer $AISA_API_KEY"
```

## Supported parameters

Duration defaults to 5 seconds. Reference mode requires 5–15 seconds, at least one image or video, and at most 12 assets total (up to 9 images, 3 videos and 3 audio clips). With reference video input the quote is an upper bound. For text and first-frame generation with `quality` or `turbo`, use 5–30 whole seconds. With `ultraquality` or `disabled`, use 5–15. Set `duration` to `"auto"` to estimate the length from quoted dialogue. Resolution defaults to `768p`; supported values are `480p`, `768p`, `1080p` and `2k` when priced for your model. At 1080p and 2k, select `16:9` or `9:16`. Lower resolutions also support `21:9`, `4:3`, `1:1`, and `3:4`. An optional integer `seed` ranges from 0 to 4294967295.

For `image_to_video`, pass the first frame in `image`. For `reference_to_video`, pass images in `reference_images`. Use an HTTPS URL or inline Base64. For example, a first-frame input looks like `{"type":"url","url":"https://example.com/first.png"}`. The output follows the first frame’s aspect ratio.

On the native create endpoint, retry with the same `Idempotency-Key` within 24 hours to replay the response. A concurrent duplicate returns HTTP 409. Keep the task ID for polling. For a completed task, both endpoints reuse a refreshed result URL for up to one minute per API instance. During a temporary Gateway outage, the API returns the last available URL.

The generation mode selects the per-second rate. In `reference_to_video`, image-only references use the reference-mode rate for the output seconds. For example, at a customer rate of $0.035 per second, a 5-second output costs $0.175. The additional 15-second reservation and invoice-based calculation below apply only when the request includes a reference video.

Pass up to three videos in `reference_videos`, each as an HTTPS URL or inline Base64. Each video may be up to 16 MiB. Use a stable HTTPS URL for large files: the Vercel asynchronous job envelope has a 300 KB limit on inline requests. The URL must serve the same file until the task completes. For any number of reference videos, AIsa reserves the requested output duration plus 15 seconds total at your customer rate. AIsa does not download the references. After generation, AIsa divides the verified Gateway charge by the upstream per-second rate saved at submission, then applies your saved customer rate to those billable seconds. For example, a 5-second request reserves 20 seconds; if the upstream charge corresponds to 7 seconds, you pay for 7 and the other 13 are released. If the charge is unavailable or inconsistent, settlement remains pending and is retried. For video references, input_video_duration is omitted while pending and derived from the billable seconds after settlement.

The current adapter does not support last-frame conditioning, asset uploads, or callback delivery.
