AIsa routes ByteDance Dreamina Seedance video models through BytePlus, ByteDance's official international enterprise platform. Use one AIsa API key for Seedance alongside your other models.

Seedance models are asynchronous video generation models. You can call them two ways:

- **AIsa video API**: `POST /v1/video/generations`, then poll `GET /v1/video/generations/{task_id}`. The same API serves every video model on AIsa.
- **Ark protocol**: the request and response formats of BytePlus ModelArk (Ark), so the official Ark SDK and existing Ark code work after changing only the base URL and API key. See [Ark protocol](#ark-protocol).

## AIsa video API

```bash
curl https://api.aisa.one/v1/video/generations \
  -H "Authorization: Bearer $AISA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "dreamina-seedance-2-0-fast-260128",
    "prompt": "A paper boat drifting across a calm lake at sunrise",
    "duration": 5
  }'
```

The response contains the task `id`. Poll `GET /v1/video/generations/{task_id}` until `status` is `completed` or `failed`. See [Create a video generation task](/api-reference/media-generation/createVideoGeneration) and [Retrieve a video generation task](/api-reference/media-generation/retrieveVideoGeneration).

## Ark protocol

AIsa serves the Seedance models in the BytePlus ModelArk (Ark) content generation task protocol. Paths and request and response bodies follow the official API; AIsa adds a path prefix.

| | Official ModelArk | AIsa |
| --- | --- | --- |
| Base URL | `https://ark.ap-southeast.bytepluses.com/api/v3` | `https://api.aisa.one/v1/ark/api/v3` |
| Create task | `POST /contents/generations/tasks` | Same path under the AIsa base URL |
| Query task | `GET /contents/generations/tasks/{id}` | Same path under the AIsa base URL |
| API key | ModelArk API key | AIsa API key, as `Authorization: Bearer` |

Use the BytePlus model IDs in the table above. Endpoint IDs (`ep-...`) and Volcengine Ark model names (`doubao-seedance-...`) are not accepted.

### Official Ark SDK

```python
import os
import time

from byteplussdkarkruntime import Ark

client = Ark(base_url="https://api.aisa.one/v1/ark/api/v3", api_key=os.environ["AISA_API_KEY"])

task = client.content_generation.tasks.create(
    model="dreamina-seedance-2-0-fast-260128",
    content=[{"type": "text", "text": "A paper boat drifting across a calm lake at sunrise"}],
    resolution="720p",
    ratio="16:9",
    duration=5,
)

while True:
    result = client.content_generation.tasks.get(task_id=task.id)
    if result.status in ("succeeded", "failed", "cancelled"):
        break
    time.sleep(10)

print(result.status, result.content.video_url if result.status == "succeeded" else result.error)
```

The Volcengine SDK (`volcenginesdkarkruntime.Ark`) works the same way with the AIsa base URL.

### HTTP

```bash
curl https://api.aisa.one/v1/ark/api/v3/contents/generations/tasks \
  -H "Authorization: Bearer $AISA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "dreamina-seedance-2-0-fast-260128",
    "content": [{"type": "text", "text": "A paper boat drifting across a calm lake at sunrise"}],
    "resolution": "720p",
    "ratio": "16:9",
    "duration": 5
  }'
```

```json
{"id": "video_task_..."}
```

```bash
curl https://api.aisa.one/v1/ark/api/v3/contents/generations/tasks/video_task_... \
  -H "Authorization: Bearer $AISA_API_KEY"
```

The query returns the ModelArk task object: `status` is `queued`, `running`, `succeeded` or `failed`, and a succeeded task has `content.video_url` and `usage`. Once the charge is final, the response also carries the `X-AISA-Customer-Cost-Micros-USD` header.

### Draft videos

Create a draft with `"draft": true`, then reference it from the final video with `content[].draft_task.id`, using the draft's AIsa task ID. Only your own succeeded drafts can be referenced. The final video is generated on the same provider account as the draft, and reuses the draft's parameters and input assets you leave out; it is priced with them.

### Differences from the official API

- **Task IDs** are AIsa task IDs (`video_task_...`). The SDK treats them as opaque strings. A task created on either API can be queried on both.
- **Callbacks**: `callback_url` is not supported and returns `400` (`unsupported_parameter`). Poll the task instead.
- **Assets** must be public URLs or Base64. Assets in your own ModelArk account (`asset://...`) cannot be read through AIsa.
- **Not supported**: listing tasks (`GET /contents/generations/tasks`) and cancelling or deleting tasks (`DELETE /contents/generations/tasks/{id}`). These return `501`.

### Errors

Errors use the ModelArk body, `{"error": {"code", "message", "type"}}`. `code` is the model provider's own code when it returns one (for example `permission_denied`), otherwise an AIsa code such as `insufficient_wallet_balance` or `model_not_found`. Insufficient balance returns `402`. A failure after the task was created also carries the task `id`; when it does, query that task instead of submitting the request again.
